# AX1 공통 정책 분류와 전환 인벤토리

이 문서는 현재 AX1 Skill Pack 저장소의 정책·참조자료·공통 자산을 분석해 통합 스킬팩에서 재사용할 공통 규칙과 사업계획서·문서 형식·프로젝트 프로파일에 남길 규칙을 구분한다. 현재 파일을 즉시 이동하거나 이름을 바꾸기 위한 작업지시가 아니라, 중복을 줄이면서 기존 7개 `bizplan-*`와 `ax1-presentation`의 동작·개별 설치를 보존하기 위한 전환 기준이다.

## 1. 결론

현재 `shared/core/`에 있다는 이유만으로 모든 파일을 AX1 전체 공통 정책으로 승격하면 안 된다. 실제 내용은 다음처럼 섞여 있다.

- 모든 AX1 작업에 필요한 필수 정책
- 파일 생성·수정 때만 필요한 조건부 워크플로
- 문서나 HWPX 같은 형식별 규칙
- 국가 R&D 사업계획서에만 필요한 작성·평가 규칙
- 특정 사업과 사례에만 적용할 프로파일·근거

가장 먼저 완전한 공통으로 유지할 정책은 `사용자 이해 확인`이다. 출처·불확실성, 한글·의미 기호 원문 보존과 외부 상태 변경 권한은 공통으로 분리하고, 파일·버전·연동 규칙은 실제 산출물을 생성하거나 수정하는 스킬만 조건부로 읽게 해야 한다.

KPI 프레임워크, 사업 구체화, 평가위원 관점과 PI-LAM 프로파일은 유용하지만 AX1 전체 산출물의 기본 규칙은 아니다. 문서 형식과 업무 분야에 맞는 계층에 유지한다.

## 2. 조사 범위와 현재 배포 방식

분류 기준은 다음 현재 원본과 소비 관계다.

- `shared/core/` 정책 10개
- `shared/templates/` 템플릿 8개
- `shared/profiles/` 프로파일과 템플릿
- `shared/evidence/` 근거 레지스터
- 7개 `bizplan-*`와 `ax1-presentation` 스킬의 `SKILL.md`, `references/`, `assets/`와 스크립트
- `scripts/build_release.py`의 공통 자원 복제·검증·패키징 규칙
- `AGENTS.md`, `CONTRIBUTING.md`, `docs/pr-operating-policy.md`의 저장소 운영 규칙

현재 빌드는 `shared/`의 기준 원본을 필요한 스킬의 `references/`와 `assets/`로 복사한다. 복사본 해시는 기준 원본과 일치하며, 전체 ZIP뿐 아니라 개별 스킬 ZIP에도 필요한 자원이 포함된다. 이 원칙은 통합 이후에도 유지한다.

## 3. 정책 분류 체계

| 코드 | 분류 | 적용 기준 | 예시 |
|---|---|---|---|
| `C0` | 필수 공통 정책 | 모든 AX1 스킬이 항상 적용 | 사용자 이해 확인, 권한·외부 영향 경계 |
| `C1` | 조건부 공통 워크플로 | 해당 작업 유형일 때만 읽음 | 파일 처리, 버전 전환, 산출물 연동 |
| `F` | 형식별 정책 | 특정 파일 형식을 만들거나 편집할 때 적용 | HWPX, DOCX, PPTX, XLSX 검증 |
| `D` | 업무 분야 정책 | 특정 산출물·업무 분야에서만 적용 | 사업계획서 KPI·평가·구체화 |
| `P` | 프로파일·근거 | 적용조건이 맞는 사업·사례에서만 사용 | PI-LAM 프로파일, 평가 근거 레지스터 |

한 파일이 여러 분류를 포함하면 `혼합`으로 표시하고 전환 시 분리한다. 공통 정책을 늘리는 것이 목표가 아니라, 모든 업무에 정말 필요한 최소 규칙만 공통으로 유지하는 것이 목표다.

## 5. 공통으로 승격할 최소 정책

### 5.1 작업 시작 전 사용자 이해 확인

현재 `12-user-confirmation-gate.md`를 기준 원본으로 유지한다.

- 확인 전 파일·도구·환경 조회 금지
- 목적·입력·범위·제외·산출물·가정 설명
- 별도 사용자 메시지의 명시적 동의
- 실질적 범위 변경 시 재확인
- 문서 반영, 외부 전송, 파괴적 작업 등 후속 승인과 구분

`ax1-work`가 전문 스킬로 넘길 때 같은 요청을 반복 확인하지 않게 하려면, 구현 단계에서 확인 범위를 전달하는 `confirmation envelope`를 도입한다. 목적·입력·범위·산출물 또는 외부 영향이 달라지면 전문 스킬이 다시 확인한다.

### 5.2 출처·불확실성·사실 상태

다음 항목을 정부 R&D 용어와 분리해 공통화한다.

- 사용자 지정 공식 원천과 최신 승인 원천 우선
- 상위 근거와 하위 사례의 충돌 처리
- `확인 / 가정 / 결정 필요 / 자료 필요` 구분
- 근거 없는 수치·기관·일정 생성 금지
- 동일 값의 기준 원천과 반복 위치 추적

공고문·RFP·평가의견 같은 출처 이름은 사업계획서 프로파일에서 확장한다. 일반 보고서는 계약서, 회의 결정, 업무 시스템 기록과 승인 메일 등이 상위 원천이 될 수 있다.

### 5.3 언어·의미 보존

현재 한글 보존 규칙이 `bizplan-draft`와 `bizplan-hwpx`에 흩어져 있으므로 새 공통 기준 원본이 필요하다.

- 한글을 실제 문자로 기록
- 유니코드 이스케이프·숫자 문자참조·영문 음역·ASCII 대체 금지
- 체크박스·상태 기호·단위·수식의 의미 보존
- 파일 형식 문법상 필요한 이스케이프만 허용
- 변환 후 문자 단위 readback 또는 동등한 검증

글꼴·줄간격·제목 들여쓰기 값은 언어 보존과 분리해 형식·템플릿 정책에서 관리한다.

### 5.4 권한과 부작용 경계

현재 사용자 확인과 저장소 운영 규칙에 흩어진 다음 원칙을 공통화한다.

- 읽기·진단 요청은 파일 수정 권한이 아님
- 작성·수정 요청은 외부 제출·공유 권한이 아님
- 원본 덮어쓰기·삭제·대규모 이동은 별도 승인 대상
- 실제 제출·게시·메시지 전송과 릴리즈는 별도 외부 상태 변경
- 사용자가 지정한 업무 범위를 전문 스킬 위임 과정에서 확대하지 않음

이 정책은 에이전트의 제품별 권한 체계를 대체하지 않고 AX1 작업의 사용자 기대를 명시한다.

## 6. 조건부 공통 워크플로

조건부 정책은 모든 `SKILL.md`에 본문으로 복제하지 않는다. 스킬의 해당 작업 경로에서만 참조하도록 연결한다.

### 6.1 파일 생성·수정

적용 조건은 실제 문서·프레젠테이션·스프레드시트 파일을 만들거나 수정하는 요청이다.

- 기준 파일과 출력 파일 분리
- 원본·사용자 변경 보존
- 형식별 도구와 렌더·readback 사용
- 자동 검사와 사람 시각 검증 상태 구분
- 파일 생성이 필요 없는 텍스트 요청에서는 적용하지 않음

### 6.2 산출물 버전 전환

적용 조건은 관리 산출물의 새 버전이 생기고 현재본을 바꿔야 하는 경우다.

- 산출물군과 버전 묶음 식별
- 새 후보 선생성·선검증
- 복구 명세 작성
- 이전 현재본 보관 후 새 현재본 승격
- 실패 시 기존 현재본 유지와 안전한 복구
- 읽기 전용 작업과 실제 제출 증거 제외

고정 경로 `08_작성중`, `09_검토_수정`, `10_제출본`, `98_이전버전`, `99_임시작업`은 범용 불변조건이 아니라 현재 사업계획서 작업공간 프로파일이다. 범용 `ax1-workspace`에서는 산출물 유형별 프로파일로 선택하게 한다.

### 6.3 최신 산출물 연동

적용 조건은 현재 관리 산출물의 의미가 달라지고 그 값을 소비하는 다른 활성 현재본이 있는 경우다.

- 항목별 공식·승인·주·파생·진단·증거 원천 구분
- 의미 변경 집합과 `changeSetHash`
- 영향 산출물별 `반영 필요 / 영향 없음 / 승인 필요 / 편집 불가 / 확인 불가 / 이력·증거 제외`
- 필수 후보 전체 검증 후 한 번에 승격
- 파생본의 자동 역전파와 반복 순환 방지

KPI·예산·기관 역할·실증은 사업계획서 영향 스키마다. 일반 보고서에는 일정, 담당, 의사결정, 조치상태, 실적과 첨부 증거 등 별도의 의미 필드가 필요하다.

## 7. 형식별 정책

### 7.1 범용 문서 스타일

다음은 DOCX·HWPX 등 페이지형 문서에서 재사용할 수 있다.

- 공식 양식의 제목·표·보호영역 우선
- 제목 계층, 문단 간격과 들여쓰기 일관성
- 표·그림 캡션과 본문 참조
- 표·그림 잘림, 고립 제목, 빈 페이지와 작은 글자 점검
- 문서 스타일 프로파일 작성

명사형 종결과 마침표 미사용은 모든 AX1 문서의 기본값이 아니라 정부·공공 사업계획서 프로파일이다. 일반 업무보고서, 공문, 이메일, 매뉴얼은 해당 산출물의 문체를 따른다.

### 7.2 HWPX 엔진 정책

다음은 `F-HWPX`로 유지한다.

- upstream 호환 버전과 건강검사
- 공식 양식 form-fill, canonical path, dry-run과 commit
- 승인 템플릿 SHA-256과 경량 생성 경계
- HWPX ZIP·XML·mimetype·open-safety·readback
- 표·셀 160%, 승인 템플릿 서식과 개요 들여쓰기
- 프리뷰와 실제 한컴 전체 페이지 관찰 상태

사업계획서 내용 준비도와 평가 규칙은 HWPX 엔진에서 제거하고 전문 업무 스킬이 확정한 내용을 입력으로 받는 방향이 적합하다. 전환 전까지는 `bizplan-hwpx`가 기존 기능과 호출명을 유지한다.

### 7.3 향후 형식 엔진

- DOCX: 스타일, 표, 페이지 렌더와 잘림
- PPTX: 슬라이드 구조, 오버플로, 시각 검증
- XLSX: 수식, 참조, 자료형, 오류 셀과 표시 형식
- PDF: 페이지 렌더, 텍스트·이미지, 민감정보와 최종 파일명

형식별 규칙은 공통 코어에 넣지 않고 해당 엔진의 `references/`와 테스트에 둔다.

## 8. 사업계획서 전용 정책

다음은 `D-BIZPLAN`으로 유지한다.

## 14. 빌드·배포 설계

### 기준 원본 하나

공통 정책과 자산은 `shared/`의 한 파일만 사람이 수정한다. 스킬 폴더의 복사본은 배포 결과이며 빌드에서 동기화한다.

### 선언형 자원 매핑

현재 `build_release.py`의 여러 상수와 개별 복사 구문은 동작하지만 새 스킬이 늘면 누락 위험이 커진다. 통합 전환 단계에서 가칭 `shared/skill-resource-map.json`에 다음을 선언하는 방식을 검토한다.

- 스킬명
- 기준 원본
- 스킬 안의 배포 경로
- 필수 또는 조건부 분류
- 해시 일치 검증 여부

빌드 스크립트는 이 매핑을 읽어 복사하고, `ALL_SKILLS`, 확인 게이트, 설치 문서와 패키지 목록의 집합이 정확히 일치하는지 검증해야 한다.

### 독립 설치

- 개별 ZIP은 실행 중 `shared/` 또는 다른 스킬 경로를 찾지 않는다.
- 필요한 참조자료·자산·스크립트를 스킬 내부에 포함한다.
- 전체 ZIP과 개별 ZIP에서 같은 수용 테스트가 통과한다.
- 저장소 링크·정션·개발자 로컬 절대경로를 배포물에 남기지 않는다.

## 15. 필요한 회귀 테스트

### 공통 불변조건

- 모든 배포 스킬에 확인 게이트 기준 원본의 정확한 복사본이 있음
- 확인 전 파일·도구·환경 조회를 시작하지 않음
- 읽기 전용 요청이 파일 수정으로 확대되지 않음
- 외부 제출·전송·배포는 별도 승인 없이 실행되지 않음
- 한글·의미 기호가 변환 후 보존됨

### 조건부 워크플로

- 텍스트만 요청하면 파일·버전 대장을 만들지 않음
- 새 버전 검증 실패 시 기존 현재본이 유지됨
- 의미 변경이 없으면 다른 산출물의 내용 버전을 만들지 않음
- 필수 연동 후보 실패 시 부분 승격하지 않음
- 실제 제출·서명·접수 증거를 자동 이동하지 않음

### 분리 안전성

- KPI·평가 렌즈가 일반 보고서에 자동 적용되지 않음
- 정부 R&D 명사형 문체가 이메일·매뉴얼 등 다른 산출물에 강제되지 않음
- `ax1-work`가 전문 스킬의 내용을 중복 수행하지 않음
- 현재 7개 `bizplan-*` 요청은 기존 전문 스킬로, 발표자료 요청은 `ax1-presentation`으로 라우팅됨
- 전체·개별 ZIP의 참조 해시와 실행 결과가 일치함

## 16. 전환 순서

1. 현재 파일을 이동하지 않고 이 인벤토리를 기준으로 공통·전용 경계를 리뷰
2. `ax1-work`에 필요한 최소 `C0` 정책부터 새 기준 원본으로 분리
3. 혼합 파일을 한 번에 해체하지 말고 테스트와 함께 하나씩 분리
4. 선언형 자원 매핑과 해시·패키지 불변조건 추가
5. 현재 8개 스킬을 한 개씩 새 기준 원본에 연결하고 회귀 검증
6. `ax1-work` 구현·라우팅 수용 테스트
7. `ax1-report` 도입 때 일반 보고서에 필요한 새 정책만 근거 기반으로 추가
8. 모든 설치 경로가 검증된 뒤 기존 중복·옛 기준 원본 정리

## 17. 완료 기준

공통 정책 분류 단계는 다음이 충족될 때 완료로 본다.

- 각 정책에 분류 코드와 기준 원본이 하나 있음
- 모든 스킬의 필수·조건부 참조 관계가 선언됨
- 공통과 사업계획서 전용 규칙의 혼합 파일이 분리됨
- 새 스킬이 확인 게이트·보안·개별 ZIP 검사를 우회할 수 없음
- 현재 8개 스킬의 기능·설치·호출 호환성이 유지됨
- 범용화 근거가 없는 규칙은 프로파일 또는 후보 상태로 남음

이 문서의 분류는 설계 기준이며 실제 파일 이동·스킬 수정·버전 변경은 별도 구현 작업과 사용자 확인 후 진행한다.
