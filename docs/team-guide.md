# AX1 Bizplan 팀원 안내

이 문서는 AX1 사업계획서 스킬을 설치하고 실제 프로젝트에서 사용하는 팀원을 위한 안내입니다. 터미널 명령을 직접 입력하기보다 아래 요청문을 Codex 또는 Claude에 그대로 전달하는 방식을 권장합니다.

## 핵심 요약

- 사용자 범위에 한 번 설치하면 다른 프로젝트에서도 계속 사용할 수 있습니다.
- 새 프로젝트를 만들 때마다 다시 설치할 필요는 없습니다.
- 새 버전 안내를 받았을 때만 업데이트합니다.
- HWPX를 사용할 사람은 upstream HWPX 플러그인도 사용자 범위에 한 번 설치해야 합니다.
- 프로젝트 작업공간에는 산출물군별 최신 검증본만 남고 이전본은 `98_이전버전`과 버전 이력표에서 확인할 수 있습니다.
- 실제 사업계획서, 기관명, 개인정보와 비공개 RFP는 GitHub나 개선 요청 Form에 직접 올리지 않습니다.
- 오류·개선 아이디어는 [AX1 사업계획서 스킬 개선 요청 Form](https://forms.gle/GG6GYrgboA4pnkVE6)으로 전달합니다.

## 설치 전에 준비할 것

다음 중 하나가 필요합니다.

1. GitHub 저장소 접근 권한
   - 저장소: <https://github.com/RealMyeong/ax1-bizplan>
2. GitHub 접근 권한이 없는 경우
   - 배포자가 공유한 `ax1-bizplan-v버전.zip`
   - 함께 제공된 `SHA256SUMS.txt`

GitHub에서 404 또는 권한 오류가 발생하면 반복 시도하지 말고 배포자에게 최신 Release ZIP을 요청합니다.

## HWPX를 사용할 때 먼저 준비할 것

DOCX만 사용하는 팀원은 이 단계를 건너뛸 수 있습니다. HWPX 양식 작성·수정이 필요한 팀원은 Codex 또는 Claude에 다음처럼 요청합니다.

```text
AX1 검증 upstream HWPX 플러그인을 사용자 범위에 설치해줘.

원본: https://github.com/airmang/hwpx-plugins
AX1 검증 ref: b7ab90a1db826c5fa5db024ad01dc5132d073953
1. Windows에서 uv와 uvx가 실행되는지 확인하고, 없으면 Astral 공식 방법으로 설치해줘.
2. 위 ref로 hwpx 마켓플레이스를 고정하고 hwpx-plugin을 설치해줘.
3. 설치된 python-hwpx, python-hwpx-automation, hwpx-plugin 버전을 확인해줘.
4. 앱 재시작과 새 작업이 필요하면 알려줘.
```

AX1 검증 기준은 source ref `b7ab90a1db826c5fa5db024ad01dc5132d073953`, `python-hwpx 6.2.1`, `python-hwpx-automation 7.0.2`, `hwpx-plugin 2.0.1`입니다. 설치 후 앱을 완전히 다시 시작하고 새 작업에서 환경을 확인합니다.

## Codex에 설치 요청하기

Codex의 새 작업에서 다음 내용을 그대로 요청합니다.

```text
$skill-installer를 사용해서 AX1 Bizplan 스킬을 사용자 범위에 설치해줘.

설치 원본: https://github.com/RealMyeong/ax1-bizplan
대상: 저장소의 skills 폴더에 있는 7개 스킬 전체

1. VERSION과 최신 안정 Release를 확인해줘.
2. 기존에 설치된 AX1 사업계획서 스킬이 있으면 버전과 위치를 확인하고 백업해줘.
3. 최신 버전을 사용자 범위에 설치해 새 프로젝트에서도 사용할 수 있게 해줘.
4. SKILL.md와 참조·에셋 파일이 빠짐없이 설치됐는지 확인해줘.
5. 설치 전후 버전, 설치된 스킬 목록, 검증 결과를 알려줘.
6. 다시 시작이 필요하면 알려줘.
```

GitHub에 접근할 수 없다면 Release ZIP을 Codex에 첨부하고 첫 줄을 다음과 같이 바꿉니다.

```text
첨부한 AX1 Bizplan Release ZIP과 SHA256SUMS.txt를 사용해 체크섬을 확인한 뒤 사용자 범위에 설치해줘.
```

Codex가 변경을 바로 감지하지 못할 때만 Codex를 다시 시작합니다.

## Claude Code에 설치 요청하기

Claude Code가 설치되어 있지 않다면 먼저 공식 설치 안내에 따라 설치하고 로그인합니다. Windows에서는 공식 WinGet 설치를 사용할 수 있습니다.

```powershell
winget install Anthropic.ClaudeCode
```

그다음 Claude Code에서 다음 내용을 요청합니다.

```text
AX1 Bizplan 스킬을 모든 프로젝트에서 사용할 수 있도록 사용자 스킬로 설치해줘.

설치 원본: https://github.com/RealMyeong/ax1-bizplan
원본 폴더: skills
설치 위치: ~/.claude/skills

1. VERSION과 최신 안정 Release를 확인해줘.
2. 기존 AX1 사업계획서 스킬이 있으면 먼저 백업해줘.
3. skills 폴더의 7개 스킬 디렉터리를 참조·에셋·스크립트와 함께 설치해줘.
4. 설치 전후 버전과 설치된 스킬 목록을 알려줘.
5. Claude Code가 스킬을 인식하는지 확인해줘.
```

GitHub에 접근할 수 없다면 Release ZIP을 내려받은 폴더에서 Claude Code를 열고 다음과 같이 요청합니다.

```text
이 폴더의 AX1 Bizplan Release ZIP을 풀고, 기존 버전을 백업한 뒤 skills 폴더의 7개 스킬을 ~/.claude/skills에 설치해줘. 설치 결과도 검증해줘.
```

Claude Code는 일반적으로 사용자 스킬 폴더의 변경을 실행 중에도 감지합니다. 사용자 스킬 폴더를 처음 만든 경우에만 다시 시작이 필요할 수 있습니다.

## 설치 확인

다음 7개 스킬이 보여야 합니다.

| 스킬 | 언제 사용하는가 |
|---|---|
| `bizplan-prepare` | 새 사업계획서 프로젝트의 폴더와 준비현황을 구성할 때 |
| `bizplan-draft` | 질문·답변으로 사업을 설계하고 양식에 밀도 있게 배분해 초안을 작성할 때 |
| `bizplan-hwpx` | 확정 문안을 HWPX 양식에 반영하고 한컴에서 검증할 때 |
| `bizplan-review` | 작성본을 평가위원 관점에서 검토할 때 |
| `bizplan-revise` | 검토·평가의견을 문서 전체에 일관되게 반영할 때 |
| `bizplan-preflight` | 제출 직전에 형식·수치·도표·버전을 점검할 때 |
| `bizplan-evidence-update` | 새 근거를 스킬 자체에 반영할 때. 일반 팀원은 실행하지 않고 Form으로 접수 |

Codex에서는 `$bizplan-prepare`처럼 `$`로 스킬을 지정합니다. Claude Code에서는 `/bizplan-prepare`처럼 `/`로 호출합니다. 자연어 요청만으로도 자동 선택될 수 있지만 중요한 작업은 스킬 이름을 명시하는 편이 안전합니다.

## 권장 사용 순서

### 1. 프로젝트 준비

프로젝트 최상위 폴더를 만든 뒤 공고문, RFP, 작성 양식과 참고자료를 준비합니다.

Codex:

```text
$bizplan-prepare를 사용해서 현재 프로젝트 폴더를 사업계획서 작성 작업공간으로 준비해줘. 이전버전 보관함과 산출물 버전 이력표도 만들고, 기존 파일은 이동하거나 덮어쓰지 마.
```

Claude Code:

```text
/bizplan-prepare 현재 프로젝트 폴더를 사업계획서 작성 작업공간으로 준비해줘. 이전버전 보관함과 산출물 버전 이력표도 만들고, 기존 파일은 이동하거나 덮어쓰지 마.
```

### 2. 초안 작성

전체 초안은 다음 순서로 진행합니다.

1. 공고문·RFP·양식에서 확인된 사실과 잠정 사업상 정리
2. 회차별 3~5개 핵심 질문과 답변으로 대상·사용 흐름·구현경계·자원·실증·사업화 구체화
3. 에이전트가 정리한 구현 브리프 확인·수정
4. 구현 브리프를 양식 항목·평가질문·페이지에 배분
5. DOCX 초안 작성과 전 페이지 밀도·레이아웃 확인

`초안 작성해줘`라는 요청만으로는 질문 단계를 생략하지 않습니다. 정말 바로 작성해야 할 때만 `질문 없이 가정해서 바로 작성`이라고 명시합니다.

```text
$bizplan-draft를 사용해 공고문·RFP·양식을 먼저 분석해줘.
첫 응답에서는 문서를 만들지 말고, 사업 아이디어와 구현 방식을 회차별 질문·답변으로 먼저 구체화해줘.
내 답변을 실현 가능한 과업, 연차, KPI, 실증, 사업화 구조의 구현 브리프로 정리하고 내 확인을 받아줘.
그 다음 구현 브리프를 양식 항목과 페이지에 배분한 뒤 밀도 있는 DOCX 초안을 작성해줘.
근거가 없는 수치는 가정으로 표시해줘.
```

Claude Code에서는 `$bizplan-draft`를 `/bizplan-draft`로 바꿉니다.

### 2-1. HWPX 양식 반영

공식 HWPX 양식으로 제출해야 할 때만 초안 내용을 확정한 뒤 실행합니다.

```text
$bizplan-hwpx를 사용해서 확정된 사업계획서 문안을 공식 HWPX 양식에 반영해줘.
원본은 덮어쓰지 말고 별도 버전으로 저장해줘.
먼저 양식 위치와 반영 계획을 확인하고 dry-run 후 실제 반영해줘.
구조·본문·표를 다시 읽어 검증하고, 페이지 프리뷰와 한컴 전체 페이지 확인 결과도 알려줘.
```

바이너리 `.hwp`는 직접 편집하지 않습니다. 한컴오피스에서 `.hwpx` 사본으로 변환하고 표·그림·수식·페이지가 유지되는지 확인한 뒤 사용합니다.

### 3. 사전 검토

```text
$bizplan-review를 사용해서 작성본을 공고문·RFP·평가배점표와 대조해줘. 치명적 누락, 논리·수치 불일치, KPI 증빙 가능성을 우선순위별로 정리하고 교정문안도 제시해줘.
```

### 4. 검토의견 반영

```text
$bizplan-revise를 사용해서 검토의견을 반영해줘. 한 항목을 고치면 관련 목표, KPI, 연차, 역할과 표도 함께 동기화하고 반영 대장을 만들어줘.
```

### 5. 제출 직전 점검

```text
$bizplan-preflight를 사용해서 제출 직전 상태를 점검해줘. 빈칸, 페이지, 도표, 수치, 기관명, KPI, 파일명, 버전과 민감정보를 확인하고 마지막 조치 목록을 만들어줘.
```

## 결과물 사용 원칙

- 문서 산출물은 DOCX를 기본으로 사용합니다.
- HWPX는 변환과 렌더링을 실제로 검증할 수 있을 때만 사용합니다.
- HWPX 프리뷰는 보조 확인입니다. 제출 후보는 한컴에서 첫 페이지부터 마지막 페이지까지 실제로 열어 확인합니다.
- `08_작성중`, `09_검토_수정`, `10_제출본`에는 사업계획서·발표자료·검토보고서 등 산출물군별 최신 검증본 한 묶음만 둡니다. 같은 버전의 DOCX·PDF·프리뷰·검증기록은 한 묶음입니다.
- 새 버전이 검증되면 이전 묶음은 삭제하지 않고 `98_이전버전`으로 옮기며 `산출물_버전이력.md`에서 경로와 SHA-256을 확인할 수 있습니다.
- 새 버전 검증이 끝나지 않았거나 어떤 파일이 최신인지 모호하면 기존 현재본을 이동하지 않습니다. 읽기 전용 검토도 파일을 재배치하지 않습니다.
- 공고문·RFP·원본 양식·근거자료와 서로 다른 제출 사건의 서명본·접수증은 자동 버전 정리 대상이 아닙니다.
- 생성된 수치·일정·기관 역할은 담당자가 공식 자료와 대조합니다.
- 제출본은 항상 `bizplan-preflight` 점검 후 사람이 최종 승인합니다.
- 스킬 저장소에는 프로젝트 원본과 결과물을 넣지 않습니다.

## 업데이트 방법

배포자가 새 버전을 안내하면 최초 설치 때 사용한 요청문에서 `설치`를 `업데이트`로 바꿔 요청합니다.

```text
AX1 Bizplan을 최신 안정 버전으로 업데이트해줘. 기존 버전을 백업하고, 설치 원본의 VERSION과 Release를 확인한 뒤 7개 스킬을 함께 교체해줘. 업데이트 전후 버전과 변경된 스킬, 검증 결과를 알려줘. HWPX 플러그인을 사용하는 경우 upstream 버전과 건강검사 결과도 확인해줘.
```

업데이트가 끝나면 새 작업을 열어 변경된 스킬을 한 번 호출합니다. 문제가 생기면 백업본 또는 이전 Release로 되돌려 달라고 에이전트에게 요청합니다.

## 오류·개선사항 전달 방법

[개선 요청 Form](https://forms.gle/GG6GYrgboA4pnkVE6)에 다음 내용을 적습니다.

- 사용한 에이전트와 스킬
- 사용한 스킬 버전
- 에이전트에게 요청한 내용
- 실제 결과와 기대 결과
- 사람이 직접 보완한 내용
- 반복 발생 여부와 추가 메모

실제 사업계획서 내용, 기관명, 개인정보와 비공개 평가의견은 Form에 붙여넣지 않습니다. 원본은 접근이 통제된 Drive 폴더에 두고 위치만 기록합니다. 제한 폴더 접근 권한이 없다면 배포자에게 별도로 전달합니다.
