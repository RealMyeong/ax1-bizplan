# codex-ppt-skill 검토와 AX1 적용 결정

## 검토 대상

- 원본: <https://github.com/ningzimu/codex-ppt-skill>
- 정적 검토 기준 commit: `f2ed80372f65bb05fe62dd07979b239a17ac065d`
- 원본 라이선스: MIT
- 검토일: 2026-09-02

이 문서는 원본을 그대로 설치하거나 포크하는 절차가 아니라, AX1 통합 스킬팩에 재사용할 개념과 제외할 위험 범위를 기록한다.

## 채택한 강점

1. 전체 제작 전 슬라이드별 개요를 확정하는 단계
2. 시각 방향을 문장으로 합의하고 고정하는 단계
3. 이미지형 자료에서 대표 샘플 한 장을 먼저 확인하는 단계
4. 발표자 노트를 PPTX에 함께 넣는 방식
5. 전체 생성 뒤 모든 슬라이드를 검사하는 완료 기준
6. 슬라이드 이미지를 숫자 순서로 조립하는 단순하고 재현 가능한 구조

## AX1에서 변경한 점

| 항목 | 원본 접근 | AX1 적용 |
|---|---|---|
| 기본 산출물 | 전체 슬라이드 이미지형 PPTX | 편집 가능한 네이티브와 이미지형 중 목적에 따라 선택 |
| 편집성 | 슬라이드 내부 요소 개별 편집 불가 | 모드 선택 전에 제한을 설명하고 사용자 선택을 받음 |
| 이미지 생성 | 내장 기능 또는 외부 OpenAI 호환 API | 승인된 현재 환경의 이미지 생성 기능만 사용 |
| 자격증명 | 사용자 홈의 환경파일을 통한 API 키 사용 가능 | API 키 저장·조회 기능 없음 |
| 런타임 | 가상환경과 패키지 자동 설치 가능 | 자동 설치 없음, 요구 패키지만 명시 |
| 병렬 작업 | 하위 에이전트 사용을 강하게 요구 | 실행 환경과 사용자 요청이 허용할 때만 선택적으로 사용 |
| 스타일 자산 | 다수의 예시 이미지와 샘플 문서 포함 | 바이너리 예시는 복사하지 않고 AX1 텍스트 프로파일만 제공 |
| 검증 | 이미지·노트·PPTX 조립 중심 | 구조 검사와 별도의 전체 슬라이드 시각 검증을 모두 요구 |

## 초기 버전에서 제외한 코드와 자산

- 외부 이미지 API 공급자 어댑터와 네트워크 요청
- API 키를 저장·검색하는 설정 파일
- 가상환경 생성과 패키지 자동 설치 런타임
- 후원 로고와 원본 저장소의 예제 PPTX·PDF
- 12개 스타일 미리보기 이미지와 기타 대용량 바이너리
- 원본의 작업 상태·분산 작업 스크립트

제외 이유는 AX1 초기 사용 범위를 줄이고, 자격증명·외부 전송·설치 실패와 자산 출처 위험을 피하며, 현재 저장소의 CI 내부 개별 스킬 ZIP 격리 검증 구조를 유지하기 위해서다.

## 새 로컬 조립기의 안전 경계

`skills/ax1-presentation/scripts/assemble_image_deck.py`는 원본 구현을 복사하지 않고 AX1 요구에 맞게 새로 작성했다.

- 프로젝트 최상위 안의 입력과 출력만 허용
- `slide_01`부터 연속 번호와 동일한 이미지 크기 요구
- 지원 형식·손상·16:9 또는 4:3 화면비 검사
- 기존 출력 파일 덮어쓰기 거부
- 임시 파일에 저장·재개방·ZIP CRC 검사 후 원자적으로 승격
- 한국어·영어 발표자 노트 제목 지원
- 네트워크, API와 자격증명 기능 없음

구조 검사는 PPTX가 실제 발표 화면에서 읽기 좋은지 판단하지 않는다. 최종 후보는 모든 슬라이드를 렌더링해 사람 또는 시각 검사 도구로 확인해야 한다.

## 의존성과 라이선스

이미지형 조립·구조 검사에 필요한 Python 패키지는 `Pillow`와 `python-pptx`로 제한한다. 원본 프로젝트의 MIT 고지는 `skills/ax1-presentation/THIRD_PARTY_NOTICES.md`에 포함한다. 원본 바이너리 자산은 배포하지 않는다.

## 후속 검토 기준

원본의 새 기능을 다시 검토할 때는 최신 commit을 새로 고정하고 다음을 확인한다.

- 라이선스와 자산 출처 변경
- 새 네트워크·자격증명·외부 실행 의존성
- 이미지형 PPTX의 편집성 개선 여부
- 발표자 노트와 한글 보존
- AX1 공통 확인·버전·산출물 연동 정책과의 충돌

원본 업데이트를 AX1에 자동 병합하지 않는다. 사용자 효과와 안전성을 확인한 기능만 별도 변경 조각과 수용 테스트로 통합한다.
