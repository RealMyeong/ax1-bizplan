# HWPX 문서 관리 로컬 패치 검증 (2026-09-10)

배포 연결 (2026-09-14): 이 로컬 패치는 이후 지침 정리와 함께 v0.10.2 / bizplan-hwpx v0.4.7 배포 묶음에 포함한다. 아래는 9월 10일 당시의 검증·설치 기록이며 한컴 시각 검증 대기 등 남은 제한은 계속 적용한다.

## 범위

스킬팩 공개 버전은 v0.10.1 유지. bizplan-hwpx metadata v0.4.6은 로컬 미배포 패치다. 승인 템플릿 원본·실제 업무 문서는 변경하지 않았다. 커밋·푸시·태그·릴리즈는 수행하지 않았다.

## 결과

- 기존 구현에서 신규 회귀 8건의 실패를 먼저 확인했다. 수정 후 8건 및 긴 문서 정보 입력의 잘림 방지 1건을 포함해 총 9건을 통과했다.
- `scripts/build_release.py` 전체 검증·로컬 패키지 생성 성공. 이는 GitHub 릴리즈 게시가 아니다. 기존 HWPX 수용 테스트와 신규 회귀, 격리된 패키지 검증을 포함한다.
- 설치본 `quick_validate.py` 통과. bizplan-hwpx 35개 파일을 소스와 SHA-256 대조했다. 다른 8개 스킬은 변경하지 않았다.
- 합성 v0.1 → v0.2 생성 및 구조 검사/readback으로 문서 정보, 표지 유형 중복 제거, 기존 이력 보존과 새 행 추가를 확인했다.
- 기존 합성 파일은 부모 폴더에 있는 실제 사용자 권한이 파일에는 없는 상태였다. 임시 파일 하드링크 방식이 제한된 ACL을 보존하는 경로와 일치한다.
- 새 합성 v0.2 파일은 부모의 사용자 권한을 상속했다. 실제 사용자 컨텍스트에서 읽기·쓰기 핸들 개방 성공 및 전후 SHA-256 동일을 확인했다. ACL 변경 없이 검사했다.
- 한컴 앱 실행 후 창 활성화 실패(`failed to activate captured window`)로 실제 문서 개방·전 페이지 시각 검증은 미완료다. 화면 정상 여부나 전체 페이지 조판 통과를 주장하지 않는다.

## 합성 파일 해시

테스트 자료는 저장소 외부의 제한 작업 폴더에 보관했다. 실제 사용자 문서를 테스트 자산으로 포함하지 않았다.

- v0.1: `fdffade7f116fb9d82d83c8e5e1ce84ac38be2d7ff96f6d0e99a87cfc85abfb0`
- v0.2: `cf47b49865b7ec59eb7222622465061765141228a7a1bcca7ca1ed3c74507d96`

## 제한 및 재검증

- 권한 상속 가능한 새 파일 게시를 구현했지만 부모 ACL·파일 잠금·보안 프로그램 문제까지 해소하지는 않는다. 실제 사용자 접근을 매번 확인한다.
- 이력 4행을 채운 뒤 다음 개정은 이력을 삭제하지 않고 표 확장·페이지 검증 대기로 중단한다. 긴 개정 내역의 표 높이와 페이지 넘김도 한컴에서 확인해야 한다.
- 표지에서 전체 제목에 유형이 포함된 경우 유형 슬롯만 비운다. 원래 슬롯 위치와 문단 서식은 남으므로 필요하다면 별도 승인된 디자인 개선이 가능하다.
- Windows 새 파일 복사는 덮어쓰기를 방지하지만 복사 중 가시성의 원자성을 보장하지 않는다. 복사·해시·읽기 검증을 모두 마친 뒤 전달한다.
- 기존 설치본 9개 스킬을 별도 경로에 백업한 뒤 HWPX 스킬만 업데이트했다. 기존 역사적 백업의 정리는 이 패치 작업에서 수행하지 않았다.
