# PR #7 선별 통합·긴 표 제목행 반복 검증

검증일: 2026-10-01. 기준 main: `98545675ecf8636632a506e7808bd03581b1cf2b` (v0.10.2), 검토 PR head: `99ed967dbb872bf7cced160258321cc1ef1f9f6b`. 실제 업무 문서·PI-LAM 자료·PR의 새 표지 파일은 테스트 자산에 포함하지 않았다.

## 반영·제외

- 기존 `bizplan-hwpx` 생성기에 로컬 PNG/JPEG 삽입·표와 그림 하단 캡션·순번과 참조 검사를 통합했다. 그림·캡션 제안의 기여 출처는 gslee (with Claude Code), PR #7이다.
- 한 쪽을 넘는 긴 표는 `treatAsChar=0`, `pageBreak=CELL`, `repeatHeader=1`이다. 첫 행 모든 셀은 `header=1`, 후속 행 모든 셀은 0이다. 첫 열 중앙 정렬과 제목행 지정을 구분한다. 짧은 표는 기존 inline·반복 끔을 유지하고 행 추가 후 최종 높이로 재판정한다.
- 표→캡션에도 기존 12pt가 우선한다. 그림→캡션 3pt, 캡션 뒤 일반 본문 10pt이며 제목·표 경계의 12pt와 중복하지 않는다.
- 별도 중복 스킬·PR 표지 3개·4단계 제목·기호 치환·덮어쓰기·이력 초기화·내용 일괄 삭제는 반영하지 않았다. 승인 템플릿 파일·해시는 변경하지 않았다.

## 회귀 결과

- 수정 전 제목행 반복 관련 3개 회귀 실패를 확인했다. 제목행 지정·반복 스위치가 모두 0이었고 기존 검사기도 이를 차단하지 않았다.
- 수정 후 `headless_table_layout_test.py`: 18개 통과. 첫 행 전체 지정, 긴 표의 반복 설정, 반복 스위치/첫 행 셀 한 개 누락 차단, 짧은 표 inline, 12pt 단일 경계, 재서식 멱등성, 번호 목록·기존 표 흐름 검증을 포함한다.
- `headless_media_test.py`: 13개 통과. 합성 PNG/JPEG와 두 입력 방식, 그림 원본 바이트·한글·상태 기호 보존, 표 캡션 하단 배치·여백, 재생성 시 v0.1→v0.2 이력 유지, 기존 출력 보호, 손상·누락·원격·과대·인라인 그림 차단, 중복/잘못된 캡션·미정의 참조 차단을 포함한다. 고의 변조에서 실제 BinData 누락·손상·임베드 해제·그림 개체 참조 누락을 검사기가 잡았다.
- `hwpx_metadata_test.py`: 9개 통과. 기존 담당자·표지 중복 억제·이력 누적·기준본 해시·파일 접근 게시 정책을 유지한다.
- 기존 `headless_hwpx_acceptance_test.py`, 전체 빌드(9개 스킬·개별 ZIP 격리 검사·표준 라이브러리 import 검사), `quick_validate.py`, `git diff --check` 통과.

그림 테스트 초기에 승인 표지의 로고까지 본문 그림 수로 세고, 네임스페이스 없는 문단 조각을 XML로 파싱하는 테스트 코드 오류가 있었다. 본문 그림 ID만 집계하고 텍스트 readback 방식으로 고쳐 다시 통과시켰다. 검사 기준을 느슨하게 변경하지 않았다.

## 재검증


개발 중 산출물은 별도 임시 검증 폴더에서 확인했다. 배포 승인 후 v0.10.3 전체 빌드는 경로를 확인한 저장소의 `dist/`에서 다시 수행해 현재 버전 통합·개별 ZIP의 실제 격리 검사를 통과했다. 임시 `DIST_ROOT`만 바꾼 시험 실행은 예산 패키지 검사가 표준 `dist/`를 찾기 때문에 실패했으며 최종 통과 결과로 사용하지 않는다. 공식 구조 검사기는 시스템 Python의 PyYAML을 사용했다. 스킬 실행 스크립트는 여전히 표준 라이브러리만 사용한다.

## 실제 한컴 전체 페이지 관찰

2026-10-01 Windows 한컴오피스 2024 (`Hwp.exe` 13.0.0.4049)에서 새 비식별 합성 문서를 열고 인쇄 미리보기의 1~10쪽을 순서대로 모두 관찰했다. 복구·변환·권한 경고 없이 열렸으며 기존에 열려 있던 사용자 업무 문서는 편집하지 않았다. 합성 문서를 저장하지 않고 닫은 뒤 SHA-256이 생성 직후 값과 같은지 확인했다.

| 페이지 | 실제 관찰 |
|---|---|
| 1~4 | 표지, 문서 정보, 개정 이력과 목차의 기존 승인 템플릿 배치 유지. 합성 담당자 미입력 칸은 그대로 둠 |
| 5 | 본문·목록·표 뒤 제목과 표 앞뒤 여백, 연속 제목의 중복 여백 없음, 긴 한국어·숫자 목록 후속 줄의 hanging indent 확인 |
| 6~8 | 65개 데이터 행이 3쪽으로 나뉨. 7·8쪽에 첫 행의 두 셀 모두 반복되며 첫 열 중앙·내용 셀 왼쪽 정렬 및 긴 표 뒤 본문 여백 확인 |
| 9 | PNG·JPEG 합성 색상 이미지 2개가 본문 폭 안에 표시됨. 각 그림과 하단 캡션이 같은 쪽에 있고 표 캡션도 표 아래 배치됨. 겹침·잘림·고립 캡션 없음 |
| 10 | 수준 1 제목의 새 쪽 시작, 짧은 표 및 미선택·선택·취소·확인 기호 정상 표시 |

검증 대상 SHA-256: `addd9b325163fadbdacfb24c21ece26b7dd8df1c4483ee686e1433122436cf31`. 승인 템플릿 SHA-256은 `a292a53b64c3579cf4bcb1126378106f733013ae4a0598216bfeb4b7022f1be1`로 변경하지 않았다.

쪽별 화면과 개인정보 영역을 제외한 검토용 묶음 이미지, 전체 readback, 관찰 쪽 목록 및 upstream `hwpx.visual-review.v1` 증거는 저장소 밖 제한된 임시 검증 폴더에 보관한다. 실제 업무 문서·승인 템플릿을 추가 테스트 자산으로 복사하거나 공개하지 않았다. 이전 검증 화면을 이번 새 기능의 증거로 재사용하지 않았다.

## 검증 경계와 배포

구조·CRC·XML·readback·메트릭 기반 배치 검사와 이번 합성 문서의 실제 한컴 전 페이지 관찰은 통과했다. PNG 자동 검사는 청크·CRC·압축 래스터, JPEG는 마커 구조·크기를 확인하며 임의 JPEG 전체 픽셀 디코딩 보장을 뜻하지 않는다. 한컴 화면의 관찰은 픽셀 단위의 간격 측정이나 자동 렌더 큐의 `render_checked` 영수증이 아니며, 모든 그림·용지·쪽 경계 조합의 검증으로 확대 해석하지 않는다. upstream 영수증의 선택적 Python HWPX 왕복 검사는 해당 런타임의 패키지 부재로 `skipped`일 수 있으며 별도 AX1 구조 검사와 한컴 실제 개방 결과를 구분한다.

기존 호출 흐름의 호환 보완이므로 통합 팩 패치 v0.10.3으로 배포한다. 변경 스킬은 `bizplan-hwpx` metadata 0.4.8이며 다른 스킬·upstream 플러그인·사용자 설치본·원 PR 상태는 변경하지 않는다.
