# 표 흐름 회귀 검증 기록

검증일: 2026-09-07. 실제 업무 문서는 읽기 전용 진단에만 사용했으며 이 저장소에 원문·사본·추출 본문을 포함하지 않는다.

## 재현과 보정

`scripts/headless_table_layout_test.py`의 비식별 합성 Markdown으로 수정 전 실행 시 번호 목록 들여쓰기, 짧은 표 inline, 표 앞뒤 여백 3개 테스트 실패를 확인했다. 기존 readback 검사는 통과했으므로 구조 검사 성공만으로 배치 품질을 보증할 수 없었다.

수정 후 전용 회귀는 정상 사례와 고의 변조 사례를 검사한다. 짧은 표·한 쪽 초과 긴 표·긴 한국어 글머리표·1자리/2자리 번호 목록·연속 수준 2/3 제목·수준 1 새 쪽·열 폭 변경 후 재배치·한 쪽 초과 단일 셀 중단·재서식 멱등성·머리말/꼬리말 제외 본문 높이를 포함한다. 기존 HWPX 인수 테스트는 표지/개정이력/목차 경계와 공유 서식 보존을 계속 검사한다.

## 실제 한컴 관찰

Windows 한글 2024에서 동일한 합성 생성물의 열람용 사본을 열었다. 원본 업무 문서는 GUI에서 편집하거나 저장하지 않았다.

- 합성 표지 정상 개방. 파일 손상 경고 없음.
- 본문 2문단→수준 2 제목 간격, 연속 수준 2→3 제목의 추가 여백 부재 확인.
- 목록→제목, 본문→짧은 표, 짧은 표→본문/제목/목록 경계에 여백 확인.
- 긴 한국어 글머리표와 `1.`·`10.` 번호 목록의 후속 줄 본문 정렬 확인.
- 긴 표가 항목 30/31 및 63/64 경계에서 다음 쪽으로 연결되고 마지막 조각 뒤 본문과 떨어지는 것을 확인.
- 수준 1 `2. 새 페이지`가 새 쪽에서 시작하고 그 아래 짧은 표가 정상 표시됨.

관찰 화면은 작업 대화의 한컴 화면 캡처로 제시했다. 실제 업무 정보가 포함될 수 있는 앱 전체 화면은 저장소의 테스트 자산으로 저장하지 않는다. 표지 외 전면 양식은 이번에 전체 화면별 재검토하지 않았으며 기존 인수 테스트의 불가침 경계 대조 결과를 사용한다. PDF 전 페이지 렌더·픽셀 기반 12pt 실측 또는 모든 한컴 버전의 호환성을 검증한 것은 아니다.

첫 열람 시에는 샌드박스 임시 파일의 실행 계정 전용 ACL 때문에 접근 오류가 났다. 권한 설정을 변경하지 않고 동일 바이트의 별도 열람용 사본으로 정상 개방을 확인했다. 이 환경 문제는 HWPX 구조 손상과 구분하며, 이번 표 배치 패치에서 파일 발행/권한 로직은 변경하지 않는다.

관찰과 공식 도움말 대조 중 본문 높이는 위아래 여백뿐 아니라 머리말/꼬리말 여백도 제외해야 함을 확인하여 경계 판정과 고정값 회귀 검증에 반영했다. 관찰한 합성 문서의 표 모드와 XML은 이 판정 보정 후에도 동일하다. 합성 생성물·열람용 사본의 SHA-256은 `8740253BF457F89FBBAB9592A2712F4F0AACD71B2E07CBE546F120A2C3313880`으로 일치하며 원본 업무 문서 해시도 변경되지 않았다.

## 재검증 명령

최종 실행 결과: 전용 회귀 **15개 통과**(예시 파일의 정확한 경로·해시 허용 및 비승인 바이트 차단 포함), 기존 HWPX 인수 테스트 통과, 통합 빌드 통과(9개 스킬), `quick_validate.py`의 `Skill is valid!` 확인, `git diff --check` 통과. 한컴에서 관찰한 열람용 사본도 최종 검사기로 재검사하여 위반 0건(`[]`)을 확인했다. 빌드의 기존 `v0.9.4` 표시는 로컬 검증에 사용한 버전이며 새 릴리즈 발행을 의미하지 않는다.

```powershell
python -X utf8 scripts/headless_table_layout_test.py
python -X utf8 scripts/headless_hwpx_acceptance_test.py
python -X utf8 scripts/build_release.py
python -X utf8 <skill-creator>/scripts/quick_validate.py skills/bizplan-hwpx
```

릴리즈/태그/설치본 갱신은 별도 작업이며 위 빌드는 로컬 검증용이다. 자연 쪽 넘김 위치 및 한 쪽 높이 근처 표의 inline/floating 최종 판정은 여전히 한컴 시각 확인이 필요하다.
