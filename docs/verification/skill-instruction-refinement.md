# AX1 스킬 지침 정리 검증 — 2026-09-14

배포 연결 (2026-09-14): 이 로컬 개선을 v0.10.2 배포 묶음에 포함한다. 아래의 미배포·미커밋 표기는 최초 개선·로컬 설치 완료 시점의 기록이며, 공개 배포 상태는 해당 태그의 GitHub Release와 Actions 결과로 확인한다.

배포 직전 재검증: VERSION·플러그인 버전을 0.10.2로 맞춘 Windows 전체 빌드와 통합·개별 ZIP 격리 검사가 통과했다. `quick_validate.py` 9개 스킬, HWPX metadata 회귀 9건, 스킬 참조 계약 4건, Pages 패키징 8건을 다시 통과했으며 통합 ZIP의 SHA-256과 체크섬 파일이 일치했다. 이 재검증은 한컴 시각 검증이나 새 실제 업무 문서 평가를 대신하지 않는다.

## 결과와 범위

9개 스킬의 이름·설치 경로·자동 발견·실행 기능을 유지하면서 진입 지침과 조건부 참조를 정리했다. 특정 모델/API를 하드코딩하지 않았으며 Codex·Claude에 공통으로 적용되는 업무 기준으로 작성했다. 공개 스킬팩은 v0.10.1 그대로이고 이번 변경은 미배포 로컬 개선본이다.

수정 전 미커밋 HWPX 패치를 포함한 스냅샷을 작업공간 밖이 아닌 동일 작업공간의 저장소 외부 검증 폴더에 보관했다. 그 스냅샷과 비교해 스킬의 실행 스크립트·자산 69개는 SHA-256이 같았다. 공식/승인 템플릿, HWPX 생성·서식·권한·개정 이력 구현을 재작성하지 않았다. 공통 버전·연동·설치 백업 정책 원본도 해시가 같다.

## 변경 요약

- 진입점에는 목적·호출 경계·실제 승인 조건·필요한 참조·완료 기준을 남겼다.
- 동일 요청의 최초 이해 확인은 스킬 간 공유한다. 사업 브리프·이미지 샘플·제출 같은 후속 승인 조건은 유지한다.
- 전체 작성과 좁은 수정, 채팅 문안과 파일 산출, 읽기 전용 검토를 구분한다.
- 기존 승인 브리프·자료를 재사용하며 질문 개수·회차·보고서 블록 수를 채우기 위한 절차를 제거했다.
- 공통 문서의 오래된 4단계 제목 규칙을 승인된 최대 3단계 기본값으로 맞췄다. 별도 양식이 없는 Word/HWPX 제목의 공백 0·3·5개와 제목/개요 스타일, 실제 목록 내어쓰기를 명시했다. 공식 지정 서식이 우선한다.
- 새 승인 AX1 일반 HWPX 생성과 upstream을 사용하는 기존·임의 양식 편집을 분리했다. 경량 생성에 upstream 설치를 일괄 요구하지 않는다. 후속 open-safety·한컴 검증 조건은 유지한다.
- 근거 업데이트의 개별 metadata·변경 조각과 공개 릴리즈를 분리했다. 단일 사례의 근거등급과 사용자가 지정한 팀 운영규칙 채택을 구분한다.
- 공통 실행 참조는 빌드가 각 스킬에 동일하게 복사한다. 상위 저장소의 파일이나 다른 설치 스킬에 의존하는 상대경로를 추가하지 않았다.

## 독립 행동 검증

skill-creator의 독립 평가 절차를 사용했다. 평가 에이전트에게 기대 답안이나 수정 의도를 주지 않고, 요청·스킬·최초 이해 확인 완료 상태만 제공했다. 변경 전 별도 보관본의 4개 사례와 변경 후 9개 사례를 읽기 전용으로 평가했다. 실제 업무 문서가 주어지지 않았으므로 다음 행동·질문·파일 변경 범위·검증 상태 판단까지만 확인했다.

| 사례 | 변경 후 관찰한 판단 |
|---|---|
| RFP 기반 일반 요구사항정의서, upstream 없음 | 일반 HWPX 경량 생성 경로. 사업계획서 인터뷰·자동 설치로 전환하지 않음. 생성과 후속 검증을 구분 |
| KPI 측정방법만 채팅 검토 | 해당 표·지표 정의의 읽기 전용 검토. 파일·이력 변경 없음 |
| 아이디어만 있는 전체 사업계획서 | 필요한 핵심 구현 질문과 브리프 확인. 질문과 전체 초안 동시 생성 없음 |
| 승인 브리프·확정 매핑으로 DOCX 작성 | 승인 내용을 재사용하고 작성으로 진행. 재인터뷰 없음 |
| 기존 PPTX 4번 슬라이드 기관명 오타 | 기존 모드·나머지 슬라이드 보존. 새 스토리보드·모드 선택을 요구하지 않음 |
| HWPX 생성기 통과·한컴 첫 페이지만 관찰 | 제출 준비로 판정하지 않고 한컴 전 페이지 검증 대기 |
| 예산 원장과 계획서 금액 차이만 확인 | 단위·기간·기준 원천 비교. 원장 작성/갱신·연동 대장 변경 없음 |
| 단일 평가의견의 공통 정책 적용 요청 | 근거등급과 사용자 지정 팀 정책을 구분. 자료 원문 없이 규칙·성공을 꾸미지 않음 |
| DOCX 제목·목록 서식만 변경 | 내용·사업 설계는 유지하고 최대 3단계 제목 스타일·목록 내어쓰기 적용 |

변경 전 평가에서도 일부 사례는 올바르게 처리했다. 따라서 전반적인 모델 성능 향상률을 주장하지 않는다. 확인된 차이는 upstream 조건 없는 중단 문구, 좁은 PPT 수정의 전체 제작 흐름 적용 위험, 승인 브리프 재개 안내 부족, DOCX 4단계 기본값이었다.

평가 중 발견한 근거 업데이트의 CHANGELOG/버전 충돌, 명시된 네이티브 모드의 재질문, 제목 공백의 조건부 표현을 수정했다. 마지막 항목은 기존 사용자 지정 0·3·5개를 필수 기본값으로 다시 명확히 했다.

## 자동 검증과 설치

- `python -X utf8 scripts/build_release.py`: 전체 검증·로컬 패키징 통과. 기존 HWPX, 표 배치, metadata 9건, 발표자료·예산·lint 및 배포 불변식 검사를 포함한다. 원격 릴리즈 게시가 아니다.
- `python -X utf8 scripts/skill_contract_test.py`: 4건 통과. 공통 지침 동기화, 각 스킬의 로컬 Markdown 링크 완결성, 오래된 공통 참조 거부, 자동 발견 유지 검사.
- `quick_validate.py`: 로컬 설치 9개 전부 통과.
- 설치 183개 파일을 소스와 SHA-256 대조했다. 설치 전 기존 CSV 4개의 차이는 Git CRLF/설치 LF뿐임을 확인하고 원래 바이트를 백업했다.
- 직전 설치본 9개를 한 묶음으로 보존했다. v0.10.0·v0.10.1의 오래된 백업은 보관된 공개 릴리즈 ZIP/체크섬과 완전히 일치함을 검증한 뒤 2개만 삭제했다. 공개 릴리즈에서 복구 가능하며, 출처 불명·고유 수정 가능성이 있는 역사적 백업은 유지했다.
- 커밋·푸시·태그·릴리즈·실제 사용자 문서 변경은 수행하지 않았다.

## 남은 제한

실제 업무 자료를 이용한 DOCX·PPTX·XLSX·HWPX 전 과정의 품질 평가와 한컴 전 페이지 관찰을 이번 지침 정리에서 새로 수행하지 않았다. 기존 HWPX 개정표 4행 이후의 확장 검증, 실제 사용자 접근 확인, 제출 시각 증거 조건은 그대로 남아 있다. 로컬 개선본을 사용한 실제 팀 피드백에 따라 후속 조정한다.
