## 공통 에이전트 동작

- 현재 대화와 작업 폴더에 있는 자료를 먼저 찾고 이미 제공된 파일을 다시 요청하지 않아야 함
- 자료가 일부 부족하면 결과 방향을 바꾸지 않는 범위에서 가능한 검토·작성을 진행하고 미확정 항목을 마지막에 모아야 함. 전체 초안의 핵심 사업결정은 bizplan-draft의 구체화 게이트를 우선함
- 검토·평가 요청만 받은 경우 원본 파일을 수정하지 않아야 함
- 실제 파일 수정 요청에서는 원본을 보존한 수정본과 시각 검증 결과를 보고해야 함
- PI-LAM 적용조건이 맞지 않는 문서에는 PI-LAM 사례 수치와 평가 렌즈를 강제하지 않아야 함

## bizplan-draft 대화형 설계

### 신규 전체 초안

- RFP와 빈 양식에 `초안 작성해줘`라고 요청해도 첫 응답에서 DOCX·HWPX나 전체 초안을 만들지 않아야 함
- 자료에서 파악한 내용, 실행대안·추천안과 영향도 높은 질문을 제시하고 답변을 기다려야 함
- 답변이 부분적이면 `현재까지 합의`, `실현가능성 조정`, `남은 결정`을 갱신하고 다음 핵심 질문을 이어가야 함
- 핵심 여덟 영역에 `결정 필요`가 남은 동안 전체 문서 작성으로 넘어가지 않아야 함
- 구현 브리프를 사용자에게 보여주고 진행 의사를 확인받은 뒤 양식 배분표와 문서를 작성해야 함

### 양식 배분과 밀도

- 모든 실질 작성영역을 평가질문, 핵심 주장, 근거, 수행·검증, 표현 단위와 내용 예산에 연결해야 함
- 렌더 후 큰 빈 공간을 내용 공백, 배분 불균형, 레이아웃 문제와 양식 고정영역으로 구분해야 함
- 내용 부족을 반복문장, 근거 없는 수치·형용사 또는 장식용 도표로 채우지 않아야 함

### 명시적 즉시 작성

- 사용자가 `질문 없이 가정해서 바로 작성`처럼 대화 생략을 명시한 경우에는 보수적인 실행안을 선택하고 가정·결정 필요를 공개한 뒤 진행할 수 있음
- 일반적인 `초안 작성`, `양식에 넣기` 요청은 즉시 작성 지시로 취급하지 않아야 함
