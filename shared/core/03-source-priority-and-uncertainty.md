# 출처·불확실성·근거 관리

## 근거 유형

| 유형 | 의미 | 사용 방식 |
|---|---|---|
| 공식 규칙 | 공고문, RFP, 양식, 공식 Q&A, 배점표 | 반드시 준수 |
| 승인 사실 | 프로젝트 참여기관이 확정한 수치·역할·일정 | 문서 사실로 사용 |
| 평가 관점 | 평가위원 의견 원문 | 예상 질문과 리스크 판단에 사용 |
| 대응 사례 | 작성기관의 반영내용, 타 선정본 문구 | 구조·해결방식 참고, 사실과 숫자는 복사 금지 |
| 일반 지식 | 표준, 논문, 산업자료 | 출처를 확인한 뒤 보강근거로 사용 |
| 모델 추론 | 문맥 기반 제안 | 가정으로 표시하고 확인 요청 |

## 평가의견 대비표를 읽는 방법

- 왼쪽의 평가의견과 오른쪽의 반영내용을 별도 레코드로 저장함
- 평가의견은 `어떤 문제가 지적되었는가`의 근거임
- 반영내용은 `어떤 방식으로 대응하려 했는가`의 사례임
- 반영내용이 실제로 승인되었는지, 충분했는지, 후속 평가에서 인정되었는지는 별도 자료가 없으면 알 수 없음
- 따라서 반영내용을 그대로 정답 문구나 필수 수치로 재사용하지 않음

## 수치 처리

- RFP 수치: 그대로 사용하되 산식과 단위를 확인함
- 현장 실측값: 기간, 표본, 설비·제품 범위와 함께 기록함
- 업계 비교값: 출처와 기준연도를 기록함
- 예시 숫자: `예시`라고 명시하고 새 문서에 자동 이식하지 않음
- 자료가 없는 값: `〈자료 필요〉`로 남기고 책임자를 지정함

## 충돌 처리

1. 충돌한 두 근거를 모두 기록함
2. 상위 출처를 임시 기준으로 사용함
3. 영향받는 표와 문단을 목록화함
4. 사용자 또는 책임기관 결정이 필요한 항목으로 올림
5. 결정 후 변경이력과 용어 원장을 갱신함
