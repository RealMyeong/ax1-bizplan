# 근거 누적·규칙 승격 정책

## 1. 근거등급

| 등급 | 근거 | 기본 위치 |
|---|---|---|
| A | 공식 공고, RFP, 양식, 배점표, 공식 Q&A | 범용 코어 또는 해당 공고 프로파일 |
| B | 서로 다른 사업군·전문기관에서 반복된 평가관점 | 범용 코어 후보 |
| C | 같은 사업의 여러 세부과제에서 반복된 평가관점 | 사업 프로파일 |
| D | 한 과제·한 위원의 관찰 또는 작성기관 대응 | 후보 규칙 또는 사례 |

## 2. 승격 원칙

- C등급 근거만으로 범용 코어에 승격하지 않음
- 동일 사업의 세부과제 수가 많아도 평가위원단과 RFP 구조가 공유되므로 독립 사업 근거로 계산하지 않음
- B등급 승격 시에도 반대 사례와 양식 차이를 확인함
- 공식 규칙 A는 적용범위를 명시함. 특정 공고의 규칙을 모든 공고에 확대하지 않음
- 구체적 목표값, 데이터량, 공정 수, 시험기간은 공식 공고가 아닌 한 규칙으로 승격하지 않음
- 사용자가 근거의 일반화와 별개로 팀 운영규칙 채택을 명시하면 그 결정을 다시 승인받게 하지 않음. 단, `사용자 지정 팀 정책`과 단일 관찰의 D등급 근거를 분리해 기록하며 보편적 사실·공식 의무로 주장하지 않음. 실제 적용 문안이나 예외가 아직 불명확한 부분만 확인함

## 3. 업데이트 절차

1. 새 자료의 메타데이터와 적용범위를 기록함
2. 평가의견 원문, 작성기관 대응, 실제 결과, 공식 규칙을 분리 추출함
3. 기존 렌즈와 연결하거나 새 후보 렌즈를 생성함
4. 반복 여부와 독립 사업 여부를 확인함
5. `core / profile / candidate / example` 중 하나에 배치함
6. 기존 규칙과 충돌하면 양쪽을 유지하고 충돌 사유를 기록함
7. 실제 변경된 개별 스킬 metadata 버전만 변경의 호환성에 맞춰 조정함. 참조파일마다 독립 버전을 만들지 않음
8. 테스트 사례를 추가하고 기존 동작이 깨지지 않았는지 확인함
9. 변경내역·승격/보류 사유·검증을 저장소가 정한 변경 조각에 기록함. AX1 저장소는 `.changes/<topic>.md`를 사용하며 공개 릴리즈 CHANGELOG·스킬팩 VERSION·태그는 관리자의 별도 릴리즈 작업임

## 4. 평가의견 대비표 주의사항

- 평가위원 칸은 리스크 근거임
- 반영내용 칸은 대응 아이디어임
- 반영내용이 최종 계획서에 실제 반영되었는지, 후속 평가에서 인정되었는지 별도 확인함
- 반영문안이 장황하거나 근거가 부족한 경우도 있으므로 품질을 별도 평가함
- `확인 검토 완료`, `기 반영되어 있음` 같은 답변은 실제 본문 위치와 내용이 확인되지 않으면 해소로 기록하지 않음

## 5. 버전 규칙

- 개별 스킬 metadata와 스킬팩 릴리즈 버전을 구분함. 근거 업데이트 승인이 곧 커밋·푸시·릴리즈 승인은 아님
- 기존 호출·산출물·필수 워크플로를 유지하는 지침 정리, 사례·예시·프로파일 보완은 PATCH를 기본으로 검토함
- 새로 구별되는 기능·산출물을 추가하거나 기존 사용 방식의 호환성이 달라지면 그 영향과 마이그레이션 필요를 보고함. 변경량이나 자료 개수만으로 MINOR/MAJOR를 정하지 않으며 저장소의 보수적 버전 정책을 따름

## 6. 개인정보·기밀

- 내부 계획서, 평가의견, 생산수치와 도면 정보는 배포용 Skill에 원문으로 넣지 않음
- 근거 레지스터에는 최소한의 요약, 파일명, 페이지, 비식별화된 과제구분만 기록함
- 외부 공유본은 기관명·담당자·민감 수치를 익명화함
