# 목적

사업비 관리대장을 새로 설계하지 않고 포함된 공통 양식으로 작성함. 예산 승인, 발주, 지급, 정산 승인 같은 외부 업무는 수행하지 않음.

# 작업 시작 전 사용자 이해 확인

[사용자 이해 확인](references/01-user-confirmation-gate.md)을 먼저 적용함. 목적·예상 입력자료·대상 사업과 기간·수정 범위·XLSX 산출물·주요 가정을 설명하고, 사용자가 별도 메시지로 동의한 후 파일과 도구를 사용함. 이미 확정된 항목을 반복해서 묻지 않음.

# 양식과 입력

- [공통 관리대장 XLSX](assets/templates/ax1-budget-ledger.xlsx)를 스킬 폴더 기준으로 찾음. 사용자 PC의 원본 경로나 저장소 연결에 의존하지 않음. 계약·제출기관의 필수 양식이 있으면 해당 양식을 우선함.
- [양식 명세](assets/templates/template-manifest.json)와 [양식 검사](scripts/check_budget_template.py)로 배포본 해시·빈 입력영역·구조를 확인한 후 작업공간에 사본을 만듦. 설치된 양식을 직접 수정하지 않음.
- 대상 사업코드, 관리기간, 승인예산 기준자료, 구매·집행자료와 현재 관리대장을 확인함. 자료가 없으면 양식 사본과 미확보 항목까지만 제공하고 금액·기관·거래를 지어내지 않음.
- 기본 결과는 XLSX임. HWPX 양식에 원장을 옮기거나 PDF로만 대체하지 않음. 사업계획서 본문은 `bizplan-draft`, HWPX 보고서는 `bizplan-hwpx`, 발표자료는 `ax1-presentation`으로 구분함.

# 작성·갱신

[관리대장 작성 기준](references/02-ledger-authoring.md)을 읽고 현재 환경에서 제공하는 스프레드시트 편집·검증 도구를 사용함. Codex의 스프레드시트 스킬이 있으면 함께 적용하고, Claude 등에서는 동등한 XLSX 보존·계산 검증 기능을 사용함. 도구가 없거나 기능을 보존할 수 없으면 사본·입력 매핑까지 제공하고 실제 작성 완료로 보고하지 않음. 임의 외부 전송이나 패키지 자동 설치를 요구하지 않음.

1. 승인예산을 `02_승인예산`에 먼저 매핑하고, 세부 품목·용역을 `01_구매비용원장`의 예산라인ID에 연결함.
2. 입력 셀만 채우고 자동계산 셀·표·차트·드롭다운·서식을 보존함. 기존 원장 갱신은 해당 기준본의 사본에서 수행함.
3. 재계산 후 예산→원장→통합현황의 금액과 경고를 대조함. 원 단위와 천원 단위를 구분하며 승인·정산 판단은 실제 근거로 확인함.
4. [산출물 파일명·버전](references/03-artifact-version-management.md)에 따라 새 사업비 원장은 `DXS-[사업코드]-BUD-[파일제목]-[YYYYMMDD]-vX.Y.xlsx`로 저장함. 템플릿 v1.1과 프로젝트 문서 버전을 혼동하지 않음.
5. [최신 산출물 연동](references/04-artifact-synchronization.md)에 따라 예산 변경의 영향 문서만 함께 검토함. 검증 전 현재본을 덮어쓰거나 이전본을 이동하지 않음. 필요한 이력은 [버전 이력](assets/artifact-version-ledger-template.md)과 [연동현황](assets/artifact-sync-ledger-template.md)을 사용함.

# 완료 보고

작성·갱신한 XLSX, 기준자료·단위, 반영·미확정 항목, 수식·구조·재계산·시각검증 결과와 미검증 사항을 보고함. 템플릿 검사를 통과한 것만으로 실제 금액이나 정산이 검증됐다고 하지 않음.

# 설치·업데이트 시

스킬 설치·업데이트가 요청된 경우에만 [직전 버전 백업 정책](references/13-skill-backup-retention.md)을 적용함. 일반 문서 작성으로 스킬 백업을 삭제하지 않음.
