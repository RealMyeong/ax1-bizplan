# AX1 스킬 설치·업데이트 백업

스킬팩 설치·업데이트 요청에만 적용함. 문서 작성만으로 설치본이나 백업을 정리하지 않음. 프로젝트 산출물의 `98_이전버전`, 원본 양식, 다른 플러그인·스킬, GitHub Release와 공유 드라이브의 배포 이력은 이 규칙의 대상이 아님.

## 보관 기준

- 사용자별·제품별 설치 범위마다 **현재 설치본 + 직전 설치 버전 백업 한 묶음**만 유지함. 예: 0.9.3에서 0.9.4로 업데이트하면 0.9.3을 보관하고 기존 0.9.2 스킬 백업은 업데이트 성공·검증 후 삭제함.
- `직전 버전`은 실제로 교체한 설치본임. 0.9.2에서 0.9.4로 건너뛰었다면 0.9.2를 보관함. 팩 버전과 개별 스킬 metadata 버전은 별개이므로 각 스킬의 실제 버전·해시도 기록함.
- 같은 버전·같은 해시의 재설치는 변경 없음으로 처리하며 백업을 회전하지 않음. 같은 버전인데 로컬 내용이 다르면 변경본을 별도 보존하고 덮어쓰기 여부를 확인함. 버전 표시만으로 미배포 수정본을 삭제하지 않음.
- 최초 설치에는 이전 설치본이 없으므로 빈 백업을 만들지 않음. 실패한 설치·검증이나 롤백 도중에는 어떤 이전 백업도 삭제하지 않음.

## 안전한 전환

1. 설치 원본의 안정 Release·체크섬과 포함 스킬 목록을 확인하고 설치 경로를 확정함. Codex·Claude의 설치본과 백업은 서로 섞지 않음.
2. 설치 루트 밖의 전용 `skills-backups` 아래에 교체 전 AX1 스킬 전체를 한 묶음으로 백업함. 사용자 설정·다른 스킬은 제외함. 백업 명세에는 제품, 설치 루트, 이전·대상 팩 버전(확인 불가 시 미확인), 개별 스킬 버전, 상대경로별 SHA-256, 백업시각을 기록함.
3. 백업 사본의 파일 목록·해시를 원본과 대조한 뒤 새 설치본을 교체함. 설치 결과의 모든 파일·참조·자산·스크립트가 배포 원본과 일치하는지와 스킬 구조를 검사함.
4. 검증에 성공했을 때만 방금 확보한 직전 설치본 백업을 남김. 이전에 AX1 설치 절차가 만든 것으로 확인되는 더 오래된 백업 묶음을 정리 대상으로 확정함.
5. 삭제 전 각 대상의 절대경로가 제품별 전용 백업 루트 내부인지, 남길 백업·현재 설치본·사용자 홈·프로젝트 루트가 아닌지 확인함. 심볼릭 링크·정션·재분석 지점이 있으면 따라가지 않고 중단함. 경로와 출처가 불명확한 수동 백업은 자동 삭제하지 않고 사용자에게 확인함.
6. 정확히 확인된 오래된 묶음만 삭제함. Windows에서는 PowerShell의 `-LiteralPath`로 끝까지 처리하고 광범위한 와일드카드나 다른 셸을 통한 삭제를 사용하지 않음.
7. 설치 전후 버전, 검증 결과, 남긴 직전 백업과 삭제한 백업을 보고함. 삭제본은 로컬 백업에서 복구할 수 없으며 공식 배포본은 이전 Release에서 다시 받을 수 있지만 로컬 고유 수정은 복원되지 않음을 알림.

기존 타임스탬프형 백업도 이름의 `before-v0.9.4`를 내용 버전으로 오인하지 않음. 이는 업데이트 대상 버전일 수 있음. 내부 스킬·명세·이전 설치 기록을 대조해 출처와 내용이 확인된 경우에만 전환 대상으로 취급함.
