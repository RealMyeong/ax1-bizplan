# 목적

자료를 바로 슬라이드에 밀어 넣지 않고 발표 목적과 청중의 판단 흐름을 먼저 설계한 뒤, 합의된 스토리보드를 검증 가능한 PPTX와 발표자 노트로 완성함

# 작업 시작 전 사용자 이해 확인

다른 모든 절차보다 먼저 [작업 시작 전 사용자 이해 확인](references/05-user-confirmation-gate.md)을 적용함. 최초 응답에서는 요청 목적·예상 입력자료·발표 대상과 시간·작업 범위·예상 산출물·편집성과 시각 품질의 핵심 선택을 설명하고, 사용자가 그 설명을 본 뒤 별도 메시지로 동의할 때까지 파일 조회·웹 탐색·도구 실행을 시작하지 않음. 수정사항이나 목적·대상·산출물이 실질적으로 달라지면 이해 내용을 다시 설명하고 재확인함

# 라우팅 경계

- 발표 목적·스토리·슬라이드 구성·PPTX 생성·수정·발표자 노트·전수 검증은 이 스킬을 사용함
- 국가 R&D·공모 사업계획서 본문의 신규 초안은 `bizplan-draft`, 기존 본문의 평가의견 반영은 `bizplan-revise`를 사용함
- 사업계획서와 발표자료를 함께 수정해 내용이 달라지면 [최신 산출물 간 내용 연동](references/07-artifact-synchronization.md)을 적용함
- 발표자료만 읽기 전용으로 평가해 달라는 요청은 발표 목적·근거·가독성·전달력을 검토하되 파일을 수정하지 않음

# 필수 입력과 기본값

- 필수: 발표 목적, 주 청중, 발표시간 또는 목표 슬라이드 수, 기준자료
- 권장: 반드시 전달할 메시지, 금지·민감 정보, 브랜드 또는 양식, 질의응답 예상, 최종 사용처
- 발표시간만 있으면 기본적으로 분당 1장 안팎을 시작점으로 제안하되 표지·목차·질의응답을 포함한 실제 밀도는 청중과 내용에 맞게 조정함
- 자료가 부족해도 확인 가능한 사실과 사용자 가정을 구분해 스토리보드는 제안할 수 있으나, 근거 없는 수치·실적·고객명·확정 표현을 만들지 않음

# 제작 모드

## A. 편집 가능한 네이티브 모드

- 텍스트·도형·표·차트·이미지를 슬라이드 개체로 유지해야 할 때 기본으로 추천함
- 사용 가능한 프레젠테이션 제작 도구로 PPTX를 만들고 모든 슬라이드를 렌더링해 확인함
- 적절한 제작 도구가 없으면 PPTX를 가장해 만들지 않고 스토리보드·문안·자산 목록까지 제공한 뒤 렌더러 부재를 보고함

## B. 전체 슬라이드 이미지 모드

- 강한 시각 통일성이 중요하고 개별 요소 편집이 필요하지 않을 때만 선택함
- 각 슬라이드를 16:9 이미지 한 장으로 생성한 뒤 [이미지형 PPTX 제작](references/03-image-deck-mode.md)에 따라 조립함
- 슬라이드 안의 텍스트·도형·차트는 각각 편집할 수 없음을 모드 확정 전에 명확히 설명하고 사용자의 별도 선택을 받음
- 외부 이미지 API, 제3자 API 키, 사용자 홈의 자격증명 파일과 런타임 자동 설치를 사용하지 않음. 현재 환경의 승인된 이미지 생성 기능이 없으면 네이티브 모드 또는 스토리보드 산출물로 전환함

# 단계별 게이트

[발표자료 워크플로](references/01-presentation-workflow.md)를 기준으로 다음 순서를 지킴

1. 자료와 제약 확인
2. 슬라이드별 스토리보드 제안 및 사용자 확정
3. 표현 모드와 시각 방향 제안 및 사용자 확정
4. 이미지 모드라면 대표 샘플 1장 생성·검토 및 사용자 확정
5. 전체 슬라이드 생성
6. 모든 슬라이드의 내용·시각·노트 검증
7. 현재본 승격과 완료 보고

스토리보드, 표현 모드, 이미지형 샘플처럼 결과 방향을 바꾸는 게이트는 묶어서 추정하지 않음. 사용자가 이미 구체적인 구성·스타일을 확정해 제공했으면 같은 결정을 다시 묻지 않고 확인된 값으로 진행함

# 스토리보드 원칙

[스토리보드와 시각 방향](references/02-storyboard-and-style.md) 및 [스토리보드 템플릿](assets/presentation-outline-template.md)을 사용함

- 각 슬라이드는 `한 장의 주장`, `근거`, `권장 시각`, `출처`, `발표자 노트 요점`을 가짐
- 제목은 주제명이 아니라 가능하면 청중이 기억해야 할 결론으로 작성함
- 동일 내용을 문단·표·도식에 중복해 공간을 채우지 않음
- 표와 차트의 수치는 기준자료까지 추적할 수 있게 하고, 가정은 시각적으로 구분함
- 기준자료가 사업계획서라면 KPI·예산·기간·기관 역할·과업·실증을 원문과 대조함
- 한국어는 `\uXXXX`, 숫자 문자참조, 영문 음역이나 ASCII 대체가 아니라 실제 한글 문자로 기록함

# 생성과 검증

- 네이티브 모드는 사용 가능한 프레젠테이션 제작 절차의 렌더·검수 규칙을 따름
- 이미지 모드는 승인된 슬라이드 이미지를 `scripts/assemble_image_deck.py`로 조립하고 `scripts/check_presentation.py`로 구조를 검사함
- 모든 슬라이드는 [발표자료 검증과 인계](references/04-validation-and-delivery.md) 및 [발표자료 검수표](assets/slide-review-checklist.md)로 전수 확인함. 표지와 대표 페이지만 보고 전체를 통과 처리하지 않음
- 발표자 노트는 화면 문구 반복이 아니라 강조점·전환문·수치 해석·예상 질문을 기록함
- 새 버전을 만들면 [산출물 최신본·이전버전 관리](references/06-artifact-version-management.md)를 적용함. 검증 전 기존 현재본을 이동하거나 덮어쓰지 않음
- 발표자료의 의미 변경이 다른 현재 산출물에 영향을 주면 모든 필수 후보를 함께 만들고 검증한 뒤 한 번에 승격함

# 완료 보고

- 확정된 발표 목적·청중·시간과 제작 모드
- 최종 PPTX와 필요 시 PDF·프리뷰·스토리보드 경로
- 슬라이드 수, 발표자 노트 포함 여부, 사용한 기준자료
- 전수 검증 결과와 확인하지 못한 항목
- 이미지 모드의 편집 불가 제한 또는 네이티브 모드의 남은 편집 제한
- 현재본·보관본·연동 상태와 후속 사람 검토 항목

# 금지

- 스토리보드 확정 전에 전체 PPTX를 완성하지 않음
- 이미지형 슬라이드를 편집 가능한 개체라고 설명하지 않음
- 사용자가 승인하지 않은 외부 이미지 API나 API 키를 사용·저장하지 않음
- 몇 장의 샘플만 보고 나머지 슬라이드의 시각 검증을 생략하지 않음
- 기준자료에 없는 수치·고객·실적·기관 합의를 사실처럼 만들지 않음
- 검증된 새 버전 없이 기존 PPTX를 덮어쓰거나 이전본을 삭제하지 않음
