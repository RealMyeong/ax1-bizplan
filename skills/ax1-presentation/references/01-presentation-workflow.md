# 발표자료 단계별 워크플로

## 1. 자료와 제약 확인

- 발표 목적: 의사결정, 제안, 보고, 교육, 공유 중 무엇인지
- 청중: 역할, 사전지식, 관심사, 예상 반대와 질문
- 시간: 발표시간, 질의응답, 목표 슬라이드 수
- 기준: 최신 원문, 수치 원장, 브랜드·공식 양식, 민감정보 범위
- 산출물: PPTX, PDF, 프리뷰, 발표자 노트, 스토리보드 중 필요한 항목

자료마다 기준 버전과 역할을 표시한다. 공식 자료와 승인된 원장을 상위 근거로 두고, 과거 발표자료는 구성 참고자료일 뿐 최신 사실의 기준으로 자동 사용하지 않는다.

## 2. 스토리보드 게이트

전체 제작 전에 다음을 표로 제안한다.

| 번호 | 결론형 제목 | 한 장의 주장 | 근거 | 권장 시각 | 출처 | 노트 요점 |
|---:|---|---|---|---|---|---|

- 발표의 시작·전개·마무리가 한 문장으로 이어지는지 확인한다.
- 상세 내용은 부록으로 분리하고 본편에는 의사결정에 필요한 최소 정보만 둔다.
- 사용자의 수정·승인 뒤에만 다음 단계로 넘어간다.

## 3. 모드·시각 방향 게이트

편집성, 시각 통일성, 제작시간, 도구 가용성을 비교해 네이티브 모드와 이미지 모드 중 추천안을 제시한다. 색상·타이포그래피·여백·이미지 성격·차트 스타일을 3~5개 규칙으로 적고 사용자가 선택하거나 수정하게 한다.

## 4. 샘플 게이트

- 네이티브 모드는 기존 템플릿이 불명확하거나 시각 방향의 불확실성이 큰 경우에만 대표 1~2장을 먼저 확인한다.
- 이미지 모드는 전체 생성 전에 내용과 시각 복잡도가 대표적인 슬라이드 한 장을 반드시 먼저 확인한다.
- 샘플의 문구, 계층, 대비, 밀도, 브랜드 적합성, 실제 발표 화면 가독성을 확인한다.

## 5. 전체 생성

확정된 스토리보드와 시각 규칙을 고정하고 전체를 생성한다. 자료가 부족한 슬라이드는 자리표시자를 숨기지 말고 `확인 필요` 상태로 구분한다. 이미지 모드는 전체 슬라이드에서 같은 비율·스타일·안전 여백을 유지한다.

## 6. 전수 검증

- 내용: 제목과 근거 일치, 수치·단위·용어·출처, 슬라이드 간 논리
- 시각: 잘림, 겹침, 저대비, 과밀, 해상도, 차트 축과 범례
- 구조: 슬라이드 순서, 개수, 화면 비율, 노트 매핑
- 전달: 발표시간, 전환문, 핵심 메시지 반복과 결론

치명적 오류가 있으면 수정 후 해당 슬라이드뿐 아니라 공통 스타일이 적용된 전체 슬라이드를 다시 확인한다.

## 7. 승격과 보고

새 PPTX를 기존 파일과 다른 이름으로 검증한 뒤에만 현재본으로 승격한다. 기존 현재본과 동반 PDF·프리뷰·검증기록은 같은 버전 묶음으로 보관하고 결과를 보고한다.
