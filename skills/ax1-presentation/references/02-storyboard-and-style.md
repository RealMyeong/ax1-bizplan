# 스토리보드와 시각 방향

## 슬라이드 한 장의 최소 설계

각 슬라이드는 다음 질문에 답해야 한다.

1. 청중이 이 장에서 내려야 할 판단은 무엇인가
2. 그 판단을 지지하는 근거는 무엇인가
3. 문장보다 표·차트·도식·이미지가 더 정확한가
4. 발표자가 화면 밖에서 설명할 내용은 무엇인가
5. 근거의 출처와 확정 상태는 무엇인가

## 권장 시각 프로파일

### 전문 보고형

- 밝은 배경, 짙은 본문, 한 가지 강조색
- 결론형 제목과 정렬된 표·차트 중심
- 경영진 보고, 제안, 정기 리뷰에 적합

### 기술 설명형

- 시스템 구성·흐름·인터페이스를 중심으로 계층 표현
- 구성요소 수를 줄이고 화살표의 의미를 일관되게 유지
- 아키텍처, 공정, 데이터·AI 흐름 설명에 적합

### 프로젝트 리뷰형

- 목표 대비 상태, 일정, 리스크, 다음 의사결정을 같은 문법으로 반복
- 상태색은 의미를 고정하고 색만으로 상태를 전달하지 않음
- 주간·월간 진척, 단계 심사, 실증 리뷰에 적합

프로파일은 시작점일 뿐 브랜드·공식 양식보다 우선하지 않는다.

## 정보 밀도

- 한 장에 핵심 주장 하나를 둔다.
- 본문 글머리표는 가능하면 3~5개로 제한하고 긴 설명은 노트로 옮긴다.
- 작은 글씨로 내용을 숨기지 말고 슬라이드를 나누거나 부록으로 보낸다.
- 장식 이미지는 메시지를 방해하면 제거한다.
- 표는 비교 차원, 차트는 변화·비율·관계를 보여줄 때 사용한다.

## 출처와 불확실성

- 수치·인용·시장자료에는 확인 가능한 출처를 연결한다.
- 사용자 가정, 추정, 미확정 목표는 사실과 구분한다.
- 생성 이미지가 실제 장비·현장·제품 사진처럼 오해될 수 있으면 개념 이미지임을 표시한다.
- 대외 발표에서 사용할 수 없는 내부 정보는 삭제하는 대신 가림·대체 방안을 사용자와 확인한다.
