# 목적

표지 양식에 본문을 채워 산출물 HWPX를 만들고, 서식을 팀 표준으로 고정하며, 글자가 깨지거나 잘리는 결함을 사람 눈이 아니라 폰트 메트릭으로 판정해 근거와 함께 보고함

# 작업 시작 전 사용자 이해 확인

다른 모든 절차보다 먼저 [작업 시작 전 사용자 이해 확인](references/05-user-confirmation-gate.md)을 적용함. 최초 응답에서는 요청 목적·예상 입력(HWPX 또는 마크다운 본문)·적용 범위·산출물·검증 가정을 설명하고, 사용자가 그 설명을 본 뒤 별도 메시지로 동의할 때까지 파일 확인, 검사·적용 스크립트 실행, 문서 생성·편집을 시작하지 않음. 수정사항이나 실질적인 범위 변경이 있으면 이해 내용을 다시 설명하고 재확인함. 이 확인은 한/글 시각 검증과 원본 덮어쓰기 승인을 대체하지 않음

[범위와 실행 판단](references/14-task-execution.md)을 함께 적용함. 같은 요청에서 이미 받은 동의와 확인된 자료는 다시 받지 않고, 요청한 것보다 넓은 작업으로 확대하지 않음

# 역할과 경계

- 양식 조립과 서식만 다룸. **본문 문안 자체를 쓰지 않음.** 문안 작성은 `bizplan-draft`, 기존 HWPX 양식의 빈칸 채우기는 `bizplan-hwpx`를 사용함
- 입력은 이미 확정된 마크다운 본문임. 내용이 비어 있으면 먼저 `bizplan-draft`로 확보함
- 한/글 COM이나 외부 패키지에 의존하지 않음. 표준 라이브러리로 HWPX의 XML을 직접 다루므로 한컴오피스가 없는 환경에서도 동작함
- **표지부터 목차 제목까지가 기관 제출 양식이므로 서식을 적용하지 않음. 목차 항목부터가 생성 대상임.** [불가침 구간](references/03-front-matter-lock.md)을 반드시 먼저 읽음
- 서식 값을 사용자 확인 없이 바꾸지 않음. 값은 [산출물 서식 규칙](references/01-format-rules.md)에 고정되어 있음
- 최종 확인은 사람이 한/글에서 직접 열어서 함. 검사 통과만으로 제출 가능이라고 보고하지 않음

# 서식 규칙

| 항목 | 값 |
|---|---|
| 글꼴 | 맑은 고딕 고정, 대체 폰트 금지 |
| 본문 글자 크기 | 10pt |
| 본문 줄간격 | 160% |
| 표 셀 줄간격 | 160% (본문과 같음) |
| 표 1행 | 배경 `#D9D9D9`, 세로 중간 + 가로 가운데 |
| 표 글자처럼 취급 | 지정 (On) |
| 그림 | 가운데 정렬, 글자처럼 취급, 기본 폭 140mm, 본문 폭 초과 시 줄임. 마크다운 `[[그림: 경로 \| 폭mm \| 캡션]]` 로 넣음 |
| 표·그림 캡션 | **대상 아래**. `[표 1-1] 제목` / `[그림 1-1] 제목`, 장-순번, 10pt 가운데, 위 3pt/아래 10pt. 자동 생성하지 않고 사람이 적은 캡션만 서식·위치·참조를 검사 |
| 제목 계층 | 4수준. 15/12/10.5/10.5pt bold + 위아래 간격 + 개요 스타일 태그. 4수준은 3수준과 동일 서식. **장 바로 다음의 절은 위 간격 8pt** |
| 목차 항목 | 장(굵게)·절(들여쓰기 10pt) 2단계 |
| 리스트 | 단계별 기호 `•` `-` `·` `·` (1수준은 `●` 아님) / 번호 `1.` `가.` `1)` `1)` + 내어쓰기, 최대 4수준 |
| 개정 이력 | 자동 기록. 비어 있으면 오늘 날짜 + `v0.1`, 있으면 버전을 올려 다음 빈 행에. 빈 행이 없으면 행 추가 |
| 파일명 버전 | 개정 이력 최신 버전과 동일한 조각(`_v0.x`)을 파일 이름에 유지 |
| 적용 범위 | **목차 항목부터**. 표지~목차 제목은 양식 그대로 (예외: 글자 깨짐 교정, 개정 이력 기입) |

전체 값과 제목·목차·리스트 계층의 세부는 [산출물 서식 규칙](references/01-format-rules.md)에 있음

# 본문 내용

본문 마크다운을 쓰거나 고칠 때는 [본문 내용 규칙](references/06-content-rules.md)을 적용함. 이미 확정된 본문을 받아 형식만 맞추는 경우에는 본문을 다시 쓰지 않고 발견한 내용 문제만 따로 보고함

- **산출물은 그 문서가 확정한 정보의 기록임. 본문에는 그 문서에 대한 정보만 씀**
- **본문은 모두 개조식으로 씀.** 명사형 어미(`~함` `~임` `~음` `~됨`) 또는 체언으로 끝내고 `~한다` `~이다` `~된다` 를 쓰지 않음. 한 항목에 한 사실, 한 줄. 줄글 서술 문단을 만들지 않음. 표지·양식 고정 문구와 인용문은 예외
- **주관적 해석을 쓰지 않음.** 자료에 없는 추정·평가·인과 단정(`~로 판단됨` `~로 보임` `중요함` `효과적임` `미흡함`)을 쓰지 않고 값·상태·규칙만 씀
- **상황 설명을 쓰지 않음.** 배경·경위·문제 제기·필요성(`기존에는 ~했으나` `~하는 어려움이 있음` `~때문에 필요함` `현재 ~인 상황임`)은 본문이 아님
- 작업에 대한 것(작성 과정·지시·검증 절차), 읽는 사람에 대한 것(독자·활용 방안·기대효과), 진행 상태에 대한 것(미확정·결정 필요·후속 일정)은 본문이 아님
- 값이 없으면 **칸을 비움.** 없는 수치·담당자·승인을 채우지 않고, 비어 있다는 사실을 문장으로 설명하지도 않음
- `1.1 목적`은 **이 문서 자체에 대한 설명**임. 무엇을 확정하는가·어느 범위인가·어느 기준을 따르는가 세 가지만 쓰고, 누가 공유하는지·왜 필요한지는 쓰지 않음
- `~할 수 있도록 작성한다`, `~이 기대된다`, `~는 미확정이다`, `제공자료에 따르면`, `체계적으로 관리한다`, `~로 판단됨`, `기존에는 ~했으나` 같은 문형은 고치지 않고 지움

# 표기 기본값과 용어집

숫자·날짜 표기 기본값(천 단위 콤마, 단위 붙여 쓰기, `YYYY-MM-DD`)은 [산출물 서식 규칙](references/01-format-rules.md)의 「표기 기본값」에 있음. 아직 검사하지 않으며 원고 작성 시 따름. 용어는 과제별 `용어집.md` 한 파일로 관리하고 [용어집 템플릿](assets/glossary-template.md)을 복사해 시작함. 각 산출물 1장의 용어 정의 표는 이 파일에서 발췌함

# 양식 출처

표지 구간의 기준 양식은 이 스킬의 **assets/templates/**에 있음. 사업마다 산출물 양식은 하나이므로 사업별 표지도 같은 폴더에 둠. 산출물을 **새로 만들 때**는 이 폴더의 양식에서 표지~목차 제목을 가져다 쓰고, 목차 항목과 본문을 채운 뒤 서식 규칙을 적용함

| 파일 | 용도 |
|---|---|
| `[산출물] 표지 양식.hwpx` | 빈 양식. 목차 제목이 마지막 문단. 제목·과제번호가 자리표시자 |
| `[산출물] 제조암묵지 표지.hwpx` | 채워 넣은 예시 |
| `[산출물] 청년바우처 표지.hwpx` | AI 청년바우처 사업 표지 |

양식의 표 음영은 `#D3D3EB`로 본문 규칙 색(`#D9D9D9`)과 다름. **오류가 아니며 표지 구간은 양식 색을 그대로 따름**

# 설치와 단일 원본

이 스킬은 저장소의 `skills/bizplan-artifact-format/` 이 원본임. 어느 폴더에서 작업하든 같은 파일이 쓰이게 하려면 사용자 스킬 폴더를 **저장소로 향하는 링크**로 둠

```powershell
cmd /c mklink /J "%USERPROFILE%\.claude\skills\bizplan-artifact-format" "<저장소>\skills\bizplan-artifact-format"
```

설치·업데이트 요청에만 [직전 설치본 백업](references/13-skill-backup-retention.md)을 적용함

- 사본으로 복사하면 저장소를 고쳐도 설치본은 낡은 상태로 남음. 링크면 그 문제가 없음
- 스크립트는 `Path(__file__).resolve()` 로 링크를 따라가 자기 스킬 폴더를 찾으므로 **assets/templates/** 의 표지 양식도 자동으로 찾음. 사본·ZIP 설치에서도 같음
- 기본 빈 양식이 아닌 사업별 표지를 쓸 때는 `--template` 으로 양식 경로를 직접 줌

# 시작 점검

1. 대상이 `.hwpx`인지 확인함. 바이너리 `.hwp`는 한컴오피스에서 `.hwpx`로 변환한 사본을 받은 뒤 진행함
2. `python scripts/check_artifact_format.py <파일.hwpx>`를 실행해 현재 위반 목록을 확보함
3. 위반이 없으면 수정하지 않고 그대로 보고함
4. 목차 문단을 찾지 못했다는 결과가 나오면 **경계를 추정하지 않고** 본문 시작 위치를 사용자에게 확인받음
   - 표지 양식 없이 본문만 있는 문서라고 사용자가 확인하면 두 스크립트에 `--no-front-matter` 를 주어 문서 시작부터 적용·검사함. 개정 이력표도 없으므로 보통 `--no-revision -o <출력>` 을 함께 씀. 문서 첫 문단이 장 제목이면 쪽나눔은 넣지 않음

# 작업 절차

## 0. 새로 만드는 경우 - 양식에 본문 채우기

기존 문서를 고치는 것이 아니라 **새 산출물을 만들 때**는 먼저 본문을 채움

```powershell
python <스킬>/scripts/build_artifact.py --content <본문>.md --title "<문서 제목>" --project "[과제번호 ...] <사업명>" -o <출력>.hwpx
```

`--template` 을 생략하면 스크립트가 자기 스킬 폴더의 **assets/templates/** 에서 이름에 `양식`이 든 빈 양식을 찾음. 사업별 표지(예: 청년바우처)를 쓸 때는 `--template` 으로 그 파일을 지정함

- 양식의 표지~목차 제목을 그대로 두고 그 뒤에 **목차 항목과 본문**을 이어붙인 뒤 서식 규칙까지 자동 적용함
- 목차 항목은 마크다운의 장 제목(`# `)에서 자동으로 뽑음. `--no-toc`로 끌 수 있음
- 생성하는 표는 **글자처럼 취급 지정(On) · 셀 단위로 나눔 · 제목 줄 자동 반복 끔** 상태로 만듦
- 문단마다 접히는 줄 수만큼 줄 배치 정보를 넣음. 하나만 넣으면 여러 줄이 한 자리에 겹쳐 그려짐
- 본문은 마크다운으로 씀. 목차 다음의 첫 `# 제목`부터 읽으므로 마크다운 앞부분에 표지·목차가 있어도 그대로 둠
- **그림은 본문 마크다운에 `[[그림: 경로 | 120mm | [그림 1-1] 제목]]` 으로 적으면 생성 단계가 문서 안에 넣음.** 별도 치환 단계가 없으므로 본문을 고쳐 다시 생성해도 그림이 남음. 상대경로 기준 폴더는 `--image-dir`, 생략하면 본문 마크다운이 있는 폴더
- 그림 파일이 없거나 지원하지 않는 형식이면 **문서를 만들지 않고 중단함.** 조용히 빠뜨리지 않음
- 쪽번호·병합 셀·표 안 그림은 아직 생성하지 못함. 한/글에서 넣은 뒤 `apply_artifact_format.py`로 서식만 다시 맞춤
- 마크다운 규칙과 한계는 [본문 작성과 생성](references/04-content-authoring.md)을 읽음

기존 문서의 서식만 고치는 경우에는 이 단계를 건너뜀

## 1. 원본 보존

- 원본을 덮어쓰지 않음. 기본 출력은 개정 버전을 반영한 `<이름>_v0.x.hwpx`(`--no-revision`이면 `<이름>_fmt.hwpx`)이고, `--in-place`를 쓰면 `.bak`을 먼저 만듦
- 원본 SHA-256을 기록해 완료 보고에 남김

## 2. 적용

```powershell
python scripts/apply_artifact_format.py <입력.hwpx> [--rev-note "<개정내역>"] [--rev-author "<이름>"]
```

스크립트가 처리하는 항목은 다음과 같음

- 모든 글꼴 참조를 맑은 고딕으로 통일
- **개정 이력표에 오늘 날짜와 한 단계 올린 버전(v0.x)을 기입** (비어 있으면 v0.1). 빈 행이 없으면 마지막 행을 복제해 추가. 같은 날 같은 내역이면 다시 쓰지 않음(멱등). 출력 파일 이름의 버전 조각을 같은 값으로 맞춤
- 본문·표 셀 문단 모두 160%. 내용이 같은 문단모양은 재사용하고, 값이 달라 공유할 수 없을 때만 복제함
- 제목 문단(15/12/10.5pt 굵게로 판정)에 위아래 간격·개요 스타일 태그·장 쪽나눔을 적용. 장 바로 다음의 절 제목은 위 간격을 줄임
- 목차 항목을 본문 장·절 제목에서 재생성 (장 굵게 + 절 들여쓰기). **문단 수가 원본과 달라질 수 있으며 증감을 로그에 남김.** 목차 항목이 하나도 없는 문서는 만들지 않음
- 리스트 문단에 단계별 기호(`•` `-` `·` `·`)와 내어쓰기를 적용 (1수준 옛 기호 `●` 는 `•` 로 교체). 번호 목록도 내어쓰기 적용
- 본문 표의 글자처럼 취급을 지정(On)으로 통일
- 사람이 적은 캡션 문단(`[표 1-1] 제목`)을 가운데·10pt 보통·위 3pt/아래 10pt 로 통일하고, **표 위에 놓인 표 캡션은 표 아래로 이동**. 캡션을 새로 만들지는 않음
- 본문 표 1행에 배경색·세로 중간·가로 가운데 적용. 1열만 음영인 라벨열 표는 머리행이 없는 표이므로 건너뜀
- 표지 구간이 참조하는 `borderFill` 은 고치지 않고 사본을 만들어 본문 표에만 물림
- 맑은 고딕에 글리프가 없는 문자를 대체 문자로 교체 (불가침 구간에도 적용)
- 단어가 셀보다 넓어 중간이 잘리는 열을 넓히고 여유 열에서 그만큼 뺌. 표 전체 폭은 유지함
- 줄 배치 캐시(`hp:lineseg@spacing`)를 문단 줄간격에 맞춰 재계산

내부 구조와 각 규칙이 XML 어디에 대응하는지는 [HWPX 내부 구조](references/02-hwpx-internals.md)에 있음

## 3. 검증

```powershell
python scripts/check_artifact_format.py <출력.hwpx>
```

다음을 모두 확인함

1. 위반 0건
2. 불가침 구간이 원본과 **바이트 단위로 동일** (허용 예외: 글자 깨짐 교정, 개정 이력표 기입·행 추가 — 로그와 대조)
3. `Contents/header.xml`과 `Contents/section0.xml`이 XML로 적합
4. 표 개수·ZIP 항목 수가 원본과 동일. 문단 개수는 목차 항목을 재생성하거나 개정 이력 행을 추가한 경우 **로그의 증감분만큼만** 달라야 함. 새로 만든 문서는 넣은 그림 수만큼 `BinData/` 항목이 늘어남
5. `mimetype`이 첫 항목이면서 무압축. `BinData/*` 도 무압축(압축하면 한/글이 변조로 판정해 열지 않음)
6. 개정 이력 최신 버전과 출력 파일 이름의 버전 조각이 동일
7. 사람이 한/글에서 열어 표지·표·그림·페이지를 실제로 관찰. 그림 위치·크기·쪽 넘김은 자동 검사로 보장되지 않음

1~6을 자동으로 확인하지 않고 넘어가지 않음. 7을 하지 못했으면 `한컴 시각 검증 대기`로 보고함

# 완료 보고

- 원본 경로와 SHA-256, 출력 경로
- 적용한 규칙별 건수 (스크립트 로그 그대로)
- 개정 이력에 기입한 날짜·버전·개정내역과 행 추가 여부
- 교체한 글자와 넓힌 열의 이전/이후 값
- 불가침 구간 동일 여부와 XML·구조 검사 결과
- 한/글 실제 관찰 상태
- 사용자 판단이 필요해 남겨둔 항목

# 금지

- 표지·문서정보·개정이력·목차 **제목**의 글꼴·크기·줄간격·음영·정렬 변경 (개정이력표는 **내용 기입만** 허용)
- 표지 로고 교체, 문서정보표·개정이력표의 칸 구조 변경 (예외: 개정이력표의 빈 행이 모자랄 때 마지막 행 복제 추가)
- 개정 이력 버전과 파일 이름 버전을 다르게 두기
- 목차에 쪽번호 임의 생성
- 표·그림 캡션을 대상 위에 두기
- 원본 덮어쓰기 또는 백업 없이 `--in-place` 사용
- 맑은 고딕에 없는 문자를 대체 문자 확인 없이 그대로 두기
- 열 너비를 늘리면서 표 전체 폭을 바꾸기
- 검사 통과만으로 `제출 준비 완료` 보고
- 실제 사업계획서·기관명·개인정보가 든 문서를 스킬 저장소에 추가

# 문제 해결

| 증상 | 원인과 대응 |
|---|---|
| `글꼴 목록에 맑은 고딕이 없다` | 문서가 맑은 고딕을 한 번도 쓴 적이 없음. 한/글에서 아무 글자에나 맑은 고딕을 지정해 저장한 뒤 다시 실행함 |
| `목차 문단을 찾지 못했다` | 목차 제목 문구가 다르거나 없음. 경계를 추정하지 않고 사용자에게 확인받은 뒤 진행함 |
| `넓힐 여유가 없다` | 모든 열이 이미 최소 폭임. 표를 나누거나 글자 크기를 조정해야 하므로 사용자 판단을 받음 |
| 대체 문자가 정의되지 않음 | `scripts/hwpx_format.py`의 `GLYPH_REPLACEMENTS`에 대응을 추가하고 근거를 남김 |
| 한/글에서 표 간격이 어색함 | 줄 배치 캐시는 한/글이 열 때 다시 계산함. 저장 후 다시 열어 확인함 |
