# 본문 내용 규칙

산출물 본문에 **무엇을 쓰고 무엇을 쓰지 않는지**를 정한다. 서식값은 [산출물 서식 규칙](01-format-rules.md)에, 마크다운 문법은 [본문 작성과 생성](04-content-authoring.md)에 있다.

## 원칙

**산출물은 그 문서가 확정한 정보의 기록이다. 본문에는 그 문서에 대한 정보만 쓴다.**

문서 밖의 것은 쓰지 않는다.

| 쓰지 않는 것 | 문서가 아니라 |
|---|---|
| 작성 과정, 사용자 지시, 동의, 검증 절차 | 작업에 대한 것 |
| 독자, 활용 방안, 기대효과, 공유 대상 | 읽는 사람에 대한 것 |
| 미확정, 결정 필요, 담당자 요청, 후속 일정 | 진행 상태에 대한 것 |
| 출처 파일명·경로·버전 | 근거에 대한 것. 참조문서 표에 문서명·버전으로 |

값이 없으면 **칸을 비운다.** 없는 수치·임계값·담당자·승인·기능을 채우지 않는다. 비어 있다는 사실을 문장으로 설명하지도 않는다.

## 개조식

**본문은 모두 개조식으로 쓴다.** 줄글 서술체를 쓰지 않는다.

| 항목 | 규칙 |
|---|---|
| 종결 | 명사형 어미 `~함` `~임` `~음` `~됨` 또는 체언으로 끝낸다. `~한다` `~이다` `~된다` `~하였다` 를 쓰지 않는다 |
| 단위 | 한 항목에 한 사실. 두 사실을 `~하고`, `~하며`, `~이므로` 로 잇지 않고 항목을 나눈다 |
| 분량 | 한 항목은 한 줄. 두 줄을 넘기면 하위 항목으로 쪼개거나 표로 옮긴다 |
| 문단 | 연속된 서술 문단을 만들지 않는다. 설명이 세 문장 이상이면 리스트 또는 표다 |
| 표 셀 | 셀 안의 설명문도 같은 규칙을 따른다 |
| 제목·캡션 | 원래 체언이므로 변경 없음 |

```
✗  가상 조립라인은 공정 A부터 공정 C까지로 구성되며, 각 공정은 설비 2대를
   운용하고 공정 간 재공품은 컨베이어로 이송된다.

✓  • 가상 조립라인 구성: 공정 A~C
   • 공정당 설비 2대
   • 공정 간 재공품 이송: 컨베이어
```

### 예외

다음은 개조식으로 바꾸지 않는다.

- 표지·문서정보·개정이력 등 양식 고정 문구 (불가침 구간)
- 계약·공고·고객 양식이 문장 형태를 지정한 항목
- 원문을 그대로 옮긴 인용·규격 정의문. 인용임을 알 수 있게 둔다
- 코드·명령·수식·식별자

## 주관적 해석 금지

**자료에 없는 판단·추정·평가를 쓰지 않는다.** 값·상태·규칙만 쓰고, 그것이 좋은지 나쁜지, 왜 그런지는 쓰지 않는다.

| 유형 | 쓰지 않는 표현 |
|---|---|
| 추정 | `~로 판단됨`, `~로 보임`, `~로 추정됨`, `~일 가능성이 큼`, `~으로 예상됨` |
| 평가 | `중요함`, `핵심적임`, `우수함`, `효과적임`, `충분함`, `미흡함`, `안정적임` |
| 인과 단정 | 측정·확정 근거 없이 `~가 원인임`, `~에 기인함`, `~로 인해 발생함` |
| 중요도 부여 | `특히`, `무엇보다`, `가장 큰`, `핵심` |

```
✗  • PLC 태그 82종 중 12종이 미수집 상태로, 수집률이 다소 미흡한 것으로 판단됨
✓  • PLC 태그: 총 82종 / 수집 70종 / 미수집 12종
```

원인·판정을 쓰는 경우는 **그 판정 자체가 문서가 확정하는 대상일 때뿐이다.** 불량 원인코드표·판정 기준표의 기준값은 해석이 아니라 확정값이므로 그대로 쓴다.

## 상황 설명 금지

**배경·경위·정황·필요성을 쓰지 않는다.** 문서는 확정된 결과만 기록하고, 그 결과에 이르게 된 과정은 문서 밖이다.

| 유형 | 쓰지 않는 표현 |
|---|---|
| 배경·경위 | `기존에는 ~했으나`, `종전 방식은 ~임`, `~에 따라 도입함`, `최근 ~가 증가함` |
| 문제 제기 | `현장에서는 ~하는 어려움이 있음`, `~의 한계가 있음`, `수작업에 의존함` |
| 필요성 | `~때문에 ~가 필요함`, `~를 위해 ~를 구축함`, `~의 개선이 요구됨` |
| 정황 서술 | `현재 ~인 상황임`, `~가 진행 중임`, `~단계에 있음` |

```
✗  • 기존에는 불량 발생 시 작업자가 수기로 이력을 확인해야 해 원인 파악에
     시간이 오래 걸렸으므로, 이를 개선하기 위해 역추적 화면을 구성함
✓  • 불량역추적 화면 구성: 이벤트 목록 / 공정 이력 / 설비 시계열 / 원인 후보 / 조치 이력
```

## 문서 목적

`1.1 목적`은 **이 문서 자체에 대한 설명**이다. 독자가 무엇을 얻는지, 누가 공유하는지, 왜 필요한지를 쓰는 자리가 아니다.

세 가지만 쓴다. 개조식 항목 두세 개면 끝난다.

| 쓸 것 | 예 |
|---|---|
| 무엇을 확정하는가 | 화면 구성, 항목별 표시 규칙, 항목별 원천 데이터 |
| 어느 범위인가 | AVIS 운영 화면 12종 |
| 어느 기준을 따르는가 | AVIS 표준 데이터 모델 v1.6 |

```
✗  화면 설계의 확정 기준을 개발·검수·운영 담당자가 공유하고, 각 화면 요소가
   어느 원천 데이터(PLC, MES, AVIS 자체 데이터, 운영자 입력)에서 채워지는지를
   한 문서에서 확인할 수 있도록 작성한다.

✓  • 확정 대상: AVIS 운영 화면 12종의 화면 구성, 항목별 표시 규칙, 항목별 원천 데이터
   • 데이터 항목 기준: AVIS 표준 데이터 모델 v1.6
```

`✗` 가 왜 안 되는지: `개발·검수·운영 담당자가 공유하고` 는 모든 산출물이 그렇고, `한 문서에서 확인할 수 있도록` 은 문서의 정의이며, `~작성한다` 는 작성자의 의도다. 실제 정보는 괄호 안 원천 데이터 목록 하나뿐인데 그것은 문장이 아니라 원천 데이터 표의 열이어야 한다.

## 쓰지 않는 문형

다음이 나오면 문서에 대한 정보가 아니다. 문장을 고치는 것이 아니라 **지운다.**

| 유형 | 예 |
|---|---|
| 문서가 자기 목적·작성 방식을 말함 | `~할 수 있도록 작성한다`, `~하고자 한다`, `~를 목적으로 한다`, `본 문서는 ~을 그대로 기술한다`, `임의로 ~하지 않는다` |
| 독자·효과를 말함 | `~가 공유한다`, `~에 활용할 수 있다`, `~이 기대된다`, `~에 도움이 된다` |
| 진행 상태를 말함 | `~는 미확정이다`, `~의 결정이 필요하다`, `추후 협의한다`, `별도 검토가 필요하다` |
| 자료를 주어로 삼음 | `제공자료에 따르면`, `~라고 기재되어 있다`, `검토한 결과` |
| 내용 없는 수식 | `체계적으로 관리한다`, `효율적으로 운영한다`, `유기적으로 연계한다` |
| 주관적 해석 | `~로 판단됨`, `~로 보임`, `중요함`, `효과적임`, `미흡함` |
| 상황·경위 설명 | `기존에는 ~했으나`, `~하는 어려움이 있음`, `~때문에 필요함`, `현재 ~인 상황임` |

`가상 조립라인 구성: 공정 A~C` 처럼 **대상을 주어로 한 사실**만 개조식으로 남긴다.

## 한 번만 쓴다

- 개요·범위 절의 문단과 바로 아래 표에 같은 값을 반복하지 않는다. 표가 있으면 문단은 표가 말하지 않는 것만 쓴다.
- 같은 값이 여러 절에 나오면 기준이 되는 한 곳에만 두고 나머지는 그 절을 지칭한다.

## 보존할 것

내용을 덜어내다가 다음을 잃지 않는다.

- 기존 요구사항 ID와 기능 의미. 오기·충돌을 발견하면 임의로 고치지 않고 사용자에게 확인한다
- 계약·고객이 요구한 필수 목차와 기재 의무. 이 규칙보다 우선한다
- 코드·약어의 의미. 자료에 풀이가 없으면 추측하지 않는다
- 요구사항 ID, 설비 ID, 신호 주소, 문서번호는 서로 다른 체계다. 접두어나 숫자가 같다고 대응관계를 만들지 않는다
