# 목적과 경계

RFP의 요구와 사용자의 사업 구상을 연결해 실현 가능한 사업계획서 초안 또는 미작성 항목을 완성한다. 검토만 요청하면 `bizplan-review`, 기존 의견 반영은 `bizplan-revise`를 사용한다. RFP를 참고하더라도 최종 결과가 일반 정의서·보고서라면 이 스킬로 사업 설계를 강요하지 않는다.

# 작업 시작 전 사용자 이해 확인

[사용자 이해 확인](references/12-user-confirmation-gate.md)에 따라 목적·입력·범위와 제외·산출물·주요 가정을 설명하고, 별도 메시지의 동의 뒤 자료 탐색과 작업을 시작한다. 같은 요청에서 이미 받은 동의는 스킬 전환 때문에 다시 받지 않는다. [범위와 실행 판단](references/14-task-execution.md)을 함께 적용한다.

# 자료와 기준

동의 후 대화·작업 폴더에서 공고·RFP·Q&A, 양식·작성지침·배점, 최신 승인 자료와 사용자의 아이디어·가용자원을 확인한다. 이미 제공된 자료를 다시 요구하지 않는다.

[근거와 양식 보호](references/01-core-principles.md)를 적용한다. 상충 자료는 기준 원천을 정하고, RFP가 없는 일반 초안도 가능하지만 필수요건·목표를 확정 사실로 만들지 않는다. 사실·가정·결정 필요·자료 필요를 구분한다. 출처 충돌·추정이 중요하면 [출처와 불확실성](references/03-source-and-uncertainty.md)을 읽는다.

# 초안 준비

전체 초안·빈 양식·대규모 보완은 [대화형 사업 설계](references/08-concept-feasibility.md)를 먼저 적용한다.

- 제공자료에서 이미 확인된 내용을 요약하고, 결과를 바꿀 핵심 공백만 질문한다. 질문 수나 회차를 채우려고 묻지 않는다.
- 선택이 필요한 경우 실행대안과 추천 이유를 제시한다. 답변을 기다리는 회차에 전체 문서나 양식 채움 결과를 함께 만들지 않는다.
- 대상·문제, 사용·가치, 구현 흐름, 구현경계·역할, 가용자원, 과업·연차, KPI·실증, 도입·사업화의 핵심 선택을 정리한다. 해당 사업에 적용되지 않는 항목은 근거와 함께 미해당으로 두며 새 사업 범위를 발명하지 않는다.
- 예산·기간·인력·데이터·외부 의존성에 맞춰 구상을 조정하고, 사용자 원안을 변경한 이유를 설명한다.
- 전체 초안 전에 구현 브리프의 선택·범위·가정을 보여주고 양식 배분과 작성 방향을 확인받는다. 이미 승인된 동일 브리프는 재인터뷰하지 않는다.
- 좁은 항목 보완은 확정된 상위 사업 설계를 재사용하고 그 항목의 공백만 다룬다.
- `질문 없이`·`가정해서 바로`·`인터뷰 생략`을 명시하면 최초 이해 확인 후 즉시 작성 모드를 적용한다. 보수적 실행 가정과 결정 필요를 공개하며 실측값·기관 합의를 만들지 않는다. 단순 `초안 작성해줘`는 인터뷰 생략이 아니다.

# 양식 배분과 작성

전체 양식 작성에는 [양식 배분과 밀도](references/09-form-allocation-density.md)를 적용해 모든 실질 작성영역에 평가질문·브리프 근거·주장·방법·검증·내용 예산을 연결한다. 단일 항목 요청이면 해당 항목과 직접 영향 범위만 매핑한다.

- [양식·문체](references/02-format-style-guide.md)에 따라 공식 제목·번호·표·보호영역을 보존한다. 별도 지정이 없을 때만 최대 3단계 개요와 형식별 제목 스타일을 적용한다.
- 과업은 입력·수행활동·산출물·검증·책임·시점과 의존성이 드러나게 쓴다. 기술명 나열 대신 사용자와 작동·운영 흐름을 설명한다.
- KPI가 있으면 [유형별 측정 기준](references/04-kpi-framework.md)과 필요 시 [지표 원장](assets/indicator-ledger-template.csv)을 사용한다. 모든 지표에 공인시험이나 같은 시험 필드를 강제하지 않는다.
- [PI-LAM 프로파일](references/05-project-profile.md)은 적용 사업·분야가 맞을 때만 읽고, 사례 수치를 새 사업 목표로 복사하지 않는다.
- 큰 빈 공간은 내용 누락·배분 불균형·레이아웃·양식 고정영역으로 구분한다. 반복 문장·장식 도표·근거 없는 수치로 채우지 않는다.

# 문서 생성·완료 기준

텍스트 요청이면 직접 삽입 가능한 문안을 제공한다. 파일 요청의 기본은 DOCX이며 지정 형식이 우선한다. 실제 파일 작업에만 [파일 처리·시각 검증](references/07-artifact-workflow.md)을 읽는다. HWPX는 내용 확정 후 `bizplan-hwpx`의 양식별 경로를 사용하고 바이너리 HWP를 직접 편집하지 않는다.

필수 항목 누락, 수치·용어·역할·연차 정합성, 출처와 가정, 형식별 전 페이지의 큰 공백·잘림·고립 제목을 확인한다. 렌더나 한컴 검증을 못 했으면 그 상태를 그대로 보고한다.

새 관리 산출물은 [파일명·버전](references/10-artifact-version-management.md), 의미 변경은 [최신본 연동](references/11-artifact-synchronization.md)을 적용한다. 필수 연동 후보까지 검증한 뒤 기존 묶음을 `98_이전버전`에 보관하고 두 이력을 갱신한다.

결과물 또는 문안, 주요 선택·근거, 남은 결정·자료, 수행한 검증과 한계를 보고한다. 전체 초안의 구현 브리프·양식 배분표는 추적 가능하게 남기되 채팅에 장문의 작업 기록을 반복하지 않는다.

설치·업데이트 요청에만 [직전 설치본 백업](references/13-skill-backup-retention.md)을 적용한다.
