# 목적과 경계

새 공고·평가·선정/탈락·보완 결과를 근거로 사업계획서 스킬의 규칙과 사업 프로파일을 유지한다. 일반적인 스킬 편집 전체에 적용하는 절차가 아니며, 개별 계획서 작성·검토도 이 스킬의 범위가 아니다.

# 작업 시작 전 사용자 이해 확인

[사용자 이해 확인](references/06-user-confirmation-gate.md)에 따라 목적·예상 자료·분석/변경 범위와 제외·산출물·주요 가정을 설명하고, 별도 메시지의 동의 뒤 자료·스킬 탐색과 작업을 시작한다. [범위와 실행 판단](references/14-task-execution.md)을 적용한다.

# 근거 분류와 결정

동의 후 대화·폴더의 새 자료와 기존 스킬을 찾고 [규칙 승격 정책](references/01-update-policy.md)을 읽는다. 분석만 요청하면 파일을 수정하지 않는다.

1. 자료명·사업·연도·기관·결과·버전·위치를 기록하고 공식 자료, 평가의견, 작성기관 대응, 실제 결과를 분리한다. 원문은 수정하지 않는다.
2. 의견 원문·대상 위치·요구·공식 근거·대응·해소 증거·적용 분야를 [근거 레지스터](assets/evidence-register-template.csv)에 연결한다.
3. [코어](references/02-core-principles.md)와 [기존 렌즈](references/03-current-evaluator-lens.md)를 비교한다. 사업 조건이 맞는 경우에만 [기존 프로파일](references/04-current-project-profile.md), 새 사업이면 [프로파일 틀](references/05-profile-template.md)을 읽는다.
4. 근거를 A 공식 규칙, B 독립 사업 반복, C 동일 사업 반복, D 단일 관찰·대응으로 구분한다. 동일 사업 반복은 우선 그 프로파일에만 적용한다.
5. 코어·프로파일·후보·삭제/완화·충돌로 나눠 변경안을 제시한다. 사용자의 구체적 확인 없이 범용 코어로 자동 승격하지 않는다.

선정 결과와 특정 문안 사이의 인과를 단정하지 않는다. 평가의견 빈도를 감점 크기로 환산하지 않는다. 숫자·기관·단일 실패 사례를 보편적 규칙으로 만들거나 반대 근거를 지우지 않는다.

사용자가 명시적으로 채택한 팀 운영규칙은 증거를 일반화한 규칙과 구분한다. 채택 의사를 재질문하지 않고 `사용자 지정 팀 정책`으로 기록하되 단일 관찰의 근거등급을 올리거나 공식 의무라고 표현하지 않는다.

# 반영과 검증

업데이트까지 요청한 경우 승인된 변경 범위만 수정하고 [변경 기록](assets/change-log-template.md)을 남긴다. SKILL.md에는 판단을 바꾸는 핵심만, 상세 근거에는 적용 조건과 한계를 둔다. 호출 경계를 넓혀 다른 스킬과 충돌시키지 않는다.

참조 경로·변경 규칙의 실제 적용 사례·반례를 검증한다. 배포 자산에 실제 제출본·개인정보·기밀·민감 수치를 복제하지 않는다. 저장소가 변경 조각을 사용하면 그 방식으로 기록하며 공개 릴리즈의 CHANGELOG나 버전을 임의 갱신하지 않는다.

결과는 근거 변화, 승격·보류·충돌 결정, 수정 파일, 검증 및 부족한 근거 중심으로 보고한다. ZIP·설치·배포는 요청된 경우에만 수행한다.

설치·업데이트 요청에만 [직전 설치본 백업](references/13-skill-backup-retention.md)을 적용한다.
