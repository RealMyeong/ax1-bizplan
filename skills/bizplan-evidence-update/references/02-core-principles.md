# 범용 코어 원칙

## 1. 출처 우선순위

충돌 시 아래 순서로 판단함

1. 공고문, RFP, 공식 Q&A, 제출 시스템의 필수요건
2. 사용자가 제공한 공식 양식과 양식 안의 작성지침
3. 평가배점표와 전문기관의 보완요청
4. 프로젝트에서 승인된 사실, 수치, 역할분담, 최신 버전 문서
5. 평가위원 의견 원문
6. 다른 선정본·사례집·작성기관의 반영문안
7. 일반 지식과 모델의 추론

하위 근거가 상위 근거를 덮어쓰지 않음

## 2. 양식 잠금

- 대제목·중제목·소제목의 번호, 명칭, 순서, 들여쓰기와 표 구조를 임의 변경하지 않음
- 양식에 없는 새 장을 만들기 전에 기존 항목 안에서 수용 가능한지 먼저 검토함
- 안내문, 예시문, 삭제 지시, 글자 수, 페이지 수, 글꼴과 여백 지침을 먼저 추출함
- 양식에 보호된 셀, 기관 공통영역, 자동계산 영역이 있으면 수정하지 않음
- 양식 변경이 불가피하면 문서 본문을 바로 수정하지 않고 변경 필요성과 영향범위를 먼저 보고함

## 3. 문서 프로파일 우선

초안 작성 전 `문서 스타일 프로파일`을 작성함

- 제목 체계
- 들여쓰기 규칙
- 문장 종결 방식
- 마침표 사용 여부
- 표·그림 캡션 형식
- 본문 내 표·그림 참조 방식
- 페이지 제한과 장별 배분
- 약어와 기관명 표기

한국어 정부 R&D 문서의 기본값은 `~함`, `~임`, `~필요`와 같은 명사형 종결 및 문장 끝 마침표 미사용임. 단, 제공 양식이나 기존 문서가 다른 방식이면 실제 양식을 따름

## 4. 사실과 추론 분리

다음 상태를 구분함

- `확인`: 공식 문서나 제공 자료로 확인됨
- `가정`: 작성 편의를 위해 임시로 둔 전제
- `결정 필요`: 기관·책임자·수요기업의 합의가 필요함
- `자료 필요`: 수치, 시험조건, 시장근거 등이 없음

자료가 없으면 그럴듯한 숫자를 만들지 않고 `〈확인 필요: ...〉`로 남김

## 5. 문서 구조

- 각 항목은 `주장 → 근거 → 실행방법 → 검증방법 → 산출물` 흐름을 기본으로 함
- 상위 목표와 하위 수행내용이 같은 용어와 범위를 사용하도록 함
- 개요, 목표, 추진전략, 연차계획, 성과지표, 사업화에 동일 개념이 등장할 때 정의와 숫자를 일치시킴
- 설명이 없는 표와 그림을 장식물로 두지 않음

## 6. 도표 배치

- 가능하면 `설명 문단 → 그림/표 → 핵심 해석 문단` 순서로 배치함
- 그림 뒤에 곧바로 또 다른 그림, 표 뒤에 곧바로 또 다른 표가 이어지지 않도록 함
- 연속배치가 불가피하면 두 도표의 역할과 차이를 설명하는 짧은 연결문을 둠
- 단순히 간격을 만들기 위해 의미 없는 문장이나 도표를 추가하지 않음
- 본문에서 먼저 언급한 뒤 도표가 나오도록 하고, 캡션 번호와 본문 참조 번호를 일치시킴

## 7. 정합성과 추적성

- 동일한 수치, 기관명, 과제명, 연차, 공정 수, 모델 수, 산출물 수는 단일 원장에서 관리함
- 수정 시 최초 등장 위치만이 아니라 모든 반복 위치를 검색함
- 계획서와 발표자료가 함께 있으면 최신 기준문서를 지정하고 서로 다른 수치를 목록화함
- 변경 이유, 근거, 영향받은 장을 변경이력에 기록함

## 8. 검토의견 사용 원칙

- 평가위원 의견은 평가 관점을 파악하는 근거임
- 작성기관의 `반영내용`은 가능한 대응 사례이지, 충분성이 검증된 정답이 아님
- 선정평가의견만으로 특정 조치가 선정에 인과적으로 기여했다고 단정하지 않음
- 같은 사업의 여러 세부과제에서 반복된 지적은 우선 해당 사업 프로파일에만 반영함
