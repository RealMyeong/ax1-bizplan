# 목적과 경계

사업계획서의 공식 HWPX 양식과 AX1 일반 산출물 양식을 구분해 작성·편집·검증한다. 원본, 승인 템플릿과 검증 증거를 보존한다. 바이너리 HWP는 직접 편집하지 않고 HWPX 변환 사본을 받는다.

# 작업 시작 전 사용자 이해 확인

[사용자 이해 확인](references/07-user-confirmation-gate.md)에 따라 목적·예상 입력·범위와 제외·산출물·가정과 위험을 설명하고 별도 메시지의 동의 뒤 탐색·환경 점검·작업을 시작한다. [범위와 실행 판단](references/14-task-execution.md)을 적용한다.

문서 목적은 입력자료 이름보다 사용자가 요청한 최종 산출물을 우선해 정한다.

- 요청이 명확하면 `사업계획서 작성` 또는 `일반 산출물 작성` 선택과 근거·양식 기준을 이해 설명에 포함한다. RFP 기반 요구사항정의서는 일반 산출물이다.
- 요청이 모호하면 두 목적 각각의 입력·범위와 제외·산출물·가정과 위험·양식 차이를 설명하고 선택을 받는다. 완전한 설명 뒤 선택과 진행 동의를 함께 받으면 같은 확인을 반복하지 않는다.
- 사업계획서는 공고·RFP·공식 양식, 일반 산출물은 승인 AX1 템플릿이 기본이다. 일반 산출물의 계약·고객 필수 양식이 있으면 그것을 우선한다.

상세 분기 규칙은 최초 동의 뒤 [문서 유형별 양식 선택](references/12-document-routing.md)을 읽는다. 실질적인 목적·범위 변경만 재확인하며 브리프·복합 편집·제출 승인 등 필요한 후속 게이트를 생략하지 않는다.

# 필요한 경로만 준비

| 요청 | 경로와 먼저 읽을 자료 |
|---|---|
| 새 AX1 일반 HWPX | 포함된 승인 템플릿 + 표준 라이브러리 생성기. [서식](references/08-headless-format-rules.md), [안전 경계](references/09-headless-architecture.md), [템플릿 경계](references/10-headless-template-boundary.md), [생성 절차](references/11-headless-authoring.md) |
| 공식·고객 양식 채움, 기존 HWPX 편집, 복합 문서 | 사용 가능한 upstream `hwpx` 스킬·MCP. [호환성](references/01-upstream-compatibility.md), 공식 사업계획서이면 [공식 양식 작업](references/02-business-form-workflow.md) |
| 내용 준비·보완 | 사업계획서는 필요에 따라 `bizplan-draft`·`bizplan-revise`; 일반 산출물은 [본문 품질](references/14-general-artifact-content-quality.md) |
| 접근·버전·정보 문제 | [문서 정보·이력·접근](references/15-document-control.md), 환경 문제는 [Windows 문제 해결](references/04-windows-troubleshooting.md) |

경량 생성은 한컴·COM·pyhwpx·upstream 설치 없이 가능하다. upstream 환경 점검 실패를 경량 생성이나 문안 준비 전체의 차단으로 확대하지 않는다. 기존 임의 문서를 경량 생성기에 템플릿으로 넣지 않는다. 생성기를 통한 개정은 승인 템플릿에 새 내용을 작성하고 기존 기준본의 이력만 검증해 이어받는 방식이다.

upstream 경로에 필요한 경우만 `check_hwpx_environment.ps1`과 연결된 `mcp_server_health`의 버전·toolSurface·missingKeyTools를 확인한다. 실제 도구 표면을 조회하며 문서에 적힌 도구가 현재 있다고 추정하지 않는다. 필요한 기능이 없으면 해당 편집을 보류하고 문안·매핑 또는 사용자 동의를 받은 대안을 제공한다. 플러그인 설치는 별도 허용이 있을 때만 수행한다.

# 내용과 문서 정보

일반 산출물은 14번 본문 품질 기준으로 생성 전 문안과 생성 후 전체 readback을 검토한다. 자료가 부족하다고 사업계획서 설계를 강제하지 않는다. 작업 지침·대화·생성 로그는 독자용 본문에 넣지 않으며 필수 출처·한계·승인 이력은 남긴다.

일반 문서 생성·개정에는 15번 참조를 적용한다. 최초 작성자·검토자·사업책임자의 소속·성명·확정 날짜를 질문해 확인된 값만 넣고 미정은 빈칸으로 허용한다. 이미 받은 답은 재질문하지 않는다. 검토자 지정이 승인 완료를 뜻하지 않는다. 제목에 문서 유형이 포함되면 유형 슬롯만 중복 표시하지 않는다. 개정은 기준본·SHA-256·이력·담당자 변경을 확인해 기존 이력을 보존하고 새 행을 추가한다. 이력 초기화나 승인·서명 추정은 하지 않는다.

# 생성·편집

- [파일명·버전](references/05-artifact-version-management.md)에 따라 기준본·현재본·원본 해시를 확인한다. DXS 파일명, 개정 이력, 외부 이력과 사용자 기준이 충돌하면 저장 전에 멈춘다. 사업·문서유형 코드를 발명하지 않는다.
- 새 후보는 원본과 다른 경로, 가능하면 `99_임시작업/버전전환/<산출물군>/<새버전>`에 만든다. 검증 전 현재본을 이동·덮어쓰지 않는다.
- 경량 경로는 승인 템플릿 해시·단일 섹션, 확정 Markdown·표지 6종·버전·일자·개정내역·출력 경로를 검사하고 `scripts/build_headless_artifact.py`를 사용한다. 보호영역은 허용된 문서 정보·이력·표지 슬롯 외 변경하지 않는다.
- 임의 양식·다중 섹션·암호화·전자서명·그림·병합 셀·각주·변경추적은 upstream 경로다. upstream 코드를 복제하거나 제한적 ZIP/XML 생성을 범용 exact 편집으로 주장하지 않는다.
- upstream은 문서 지도·canonical path·revision을 확보해 `근거→문안→위치→명령→검증` 계획을 만든다. 여러 후보 위치나 구조 변경은 사용자에게 결정받는다.
- 지원되는 쓰기는 dry-run 후 확정한다. diff의 의도 범위, `expected_revision`, 서로 다른 dry-run/commit idempotency key, 재시도 시 같은 commit key, 트랜잭션·rollback·open-safety·source preservation 영수증을 확인한다. 값 검증이 deferred이면 전용 readback으로 보완한다.
- 경량 경로의 사전 게이트는 템플릿 해시와 임시 후보 전체 자동검사다. Windows는 대상 폴더 권한을 상속하는 배타적 새 파일 복사 후 해시·읽기를 검증한다. 복사 중 가시성의 원자성은 보장하지 않는다.

# 유지할 서식과 검증

정확한 값·예외와 검사 명령은 08~11번 참조를 따른다. 핵심은 실제 한글 UTF-8 보존, 본문·표 160%, 최대 3단계 스타일 제목(앞 공백 0·3·5개), 본문 목록 hanging indent, 제목·표 경계 단일 12pt, 짧은 표 글자처럼 취급·긴 표만 floating/CELL, 본문 표 1행·1열 가로/세로 중앙·나머지 왼쪽이다. 공식·고객 양식 서식을 기본값으로 덮어쓰지 않는다.

[검증과 제출 증거](references/03-verification-evidence.md)에 따라 패키지·구조·재개방·open-safety, 전체 본문/표 readback, 한글·의미 기호·필수 플레이스홀더, 파일명·이력·원본 해시를 확인한다. 구조·내용·프리뷰·한컴 전 페이지 관찰·담당자 승인은 각각 별도 상태다.

Windows 최종 경로의 읽기·수정 접근은 15번 참조에 따라 실제 사용자 계정으로 검사한다. 샌드박스의 접근 성공을 사용자 권한 통과로 대신하지 않으며 광범위 권한 변경이나 보안 우회를 하지 않는다.

프리뷰·앱 실행·첫 페이지만 보고 한컴 검증 완료라고 하지 않는다. 한컴 전 페이지 관찰과 화면 증거가 없으면 `한컴 시각 검증 대기`다. 사업계획서의 제출 후보는 `bizplan-preflight`, 일반 산출물은 본문 품질 검토와 담당자 승인까지 충족해야 한다.

# 최신본과 완료 보고

의미 변경은 [최신본 연동](references/06-artifact-synchronization.md)을 적용해 승인된 변경의 소비 문서를 함께 검증한다. 서식만의 변경은 내용으로 전파하지 않는다. 필수 후보가 미검증이면 부분 승격하지 않는다.

단계별 검증 후 기존 HWPX와 PDF·프리뷰·readback·화면 증거를 한 버전 묶음으로 `98_이전버전`에 보관하고 버전·연동 이력을 갱신한다. 실제 제출 완료 문서·서명·접수 증거는 자동 이동·변경하지 않고 정정·재제출 후보를 별도로 만든다. 보관본을 수정하거나 덮어쓰지 않는다.

결과 파일, 반영·미반영, 내용/구조/접근/시각 상태, 현재·보관·연동 상태와 남은 결정을 간단히 보고한다. 경로·해시·영수증·서식 상세검사는 검증 기록에 남기고 채팅에 매번 전부 나열하지 않는다.

설치·업데이트 요청에만 [직전 설치본 백업](references/13-skill-backup-retention.md)을 적용한다.
