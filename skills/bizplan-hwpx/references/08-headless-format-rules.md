# AX1 경량 HWPX 서식 규칙

승인 템플릿에서 새 산출물을 만드는 경량 모드의 확정 규칙이다. 값 변경은 사용자 확인과 회귀 검증을 거쳐야 한다.

| 항목 | 값 | 범위 |
|---|---|---|
| 글꼴 | 맑은 고딕 | 생성한 목차 항목·본문·본문 표 |
| 본문 | 10pt, 줄간격 160% | 표 밖 본문 |
| 표 셀 | 10pt, 줄간격 160% | 머리행과 본문 셀 전부 |
| 장·절·항 제목 | 15pt·12pt·10.5pt, 굵게 | 생성 본문 |
| 개요 수준 | `1. / 1.1 / 1.1.1 / •`, 제목 최대 3단계 | 생성 본문 |
| 제목 스타일 | `개요 1 / 개요 2 / 개요 3`의 HWPX `styleIDRef` 연결 | 생성 본문 제목 |
| 제목 앞 공백 | 수준 1·2·3에 U+0020 0·3·5개 | 생성 본문 제목 |
| 본문 목록 | 앞 공백 없이 `• `, 왼쪽 4000 HWPUNIT·첫 줄 -800 HWPUNIT hanging indent | 생성 본문 목록 |
| 제목 위 간격 | 본문·목록 뒤 수준 2~3에 1200 HWPUNIT(12pt), 연속 제목·명시적 새 쪽 첫 제목은 0 | 생성 본문 제목 |
| 표 배치 | 기본 `treatAsChar=1`, 한 쪽 본문 높이 초과 표만 `treatAsChar=0` + `pageBreak=CELL` | 본문 표 |
| 표 경계 간격 | 표↔본문·목록·제목·표 사이 1200 HWPUNIT(12pt)을 한 번만 적용 | 본문 표 경계 |
| 번호 목록 | 번호 접두어를 보존하고 그 폭에 맞는 문단 hanging indent, 앞 공백 없음 | 생성 본문 번호 목록 |
| 표 1행·1열 | 1행 전체와 1열 전체를 가로 가운데·세로 중앙, 1행은 `#D9D9D9` | 본문 표 |
| 표 내용 셀 | 1행·1열을 제외한 나머지 셀은 가로 왼쪽 | 본문 표 |
| 표 전체 폭 | 생성 전후 동일 | 열 너비 재배분 시 |
| 한글 문자 | 실제 한글 UTF-8 문자 그대로 | 표지·목차 항목·본문·목록·표 셀 |
| 개정 이력 | `개정일자 / 버전 / 개정내역 / 선택 작성자`, 확인자는 비움 | 승인 템플릿의 첫 빈 개정 행 |
| 파일명 | `DXS-[사업코드]-[문서유형]-[파일제목]-[YYYYMMDD]-vX.Y.hwpx`, 날짜·버전은 개정 이력 최신값과 일치 | 경량 출력 HWPX |

표지부터 `목 차` 제목까지는 승인 템플릿 영역이다. 표지 글꼴·크기·표 구조·음영을 본문 규칙에 맞춰 전역 변경하지 않는다. 표지 텍스트는 정해진 자리표시자 6종만 바꾸며, 공유 전역 서식은 복제한 뒤 생성 본문에만 연결한다.

개정 이력표는 표지 영역의 제한된 예외다. 승인 템플릿의 정확한 헤더와 기존 빈 행을 확인한 뒤 글자만 기록하고 표 서식·행 구조는 바꾸지 않는다. 표가 없거나 빈 행이 없고, 기존 행이 부분 입력·중복·역순이거나 파일명·외부 이력과 버전이 충돌하면 자동 보정하지 않고 출력 전에 중단한다.

`☐`, `☑`, `☒`, `✓`, `✔` 같은 상태 기호는 의미가 다르므로 자동 치환하지 않는다. 글꼴 표시 여부가 불확실하면 원문을 보존하고 최종 시각 검증 항목으로 남긴다.

확정 한글은 `\uXXXX`·`\UXXXXXXXX` 같은 유니코드 이스케이프, `&#44032;`·`&#xAC00;` 같은 숫자 문자참조, 영문 음역이나 ASCII 대체문자로 바꾸지 않는다. HWPX XML은 UTF-8 실제 한글을 기록하며, `&`·`<`·`>`처럼 XML 문법과 충돌하는 문자만 이스케이프한다.

공식 양식에 별도 체계가 없는 경량 생성 본문은 다음 구조로 기록한다. 제목 앞 공백은 탭이나 특수 공백이 아닌 일반 반각 공백(U+0020)이며, 제목 문단의 왼쪽·첫 줄 들여쓰기는 0으로 두어 이 간격을 이중 적용하지 않는다. 아래 목록의 시각적 들여쓰기는 표시를 위한 것이며 HWPX 텍스트에는 앞 공백을 넣지 않는다.

```text
1. 주요 제목
   1.1 세부 제목
     1.1.1 상세 제목
       • 설명 또는 항목
```

숫자 제목은 3단계까지만 사용하고 각 제목 문단에 템플릿의 `개요 1`·`개요 2`·`개요 3` 스타일 ID를 연결한다. Markdown의 `####` 이상 제목은 번호 접두어를 제거한 `• ` 본문 목록으로 전환한다. Markdown 원문에 앞 공백이 있더라도 HWPX 생성기는 이를 제거하고 왼쪽 4000 HWPUNIT·첫 줄 -800 HWPUNIT 문단모양으로 바꾼다. 첫 줄은 글머리표 위치 3200 HWPUNIT에서 시작하고 후속 줄은 본문 시작 4000 HWPUNIT에 맞추며, `lineseg`의 `horzpos`·`horzsize`도 같은 값으로 기록한다.

본문·목록 뒤에 수준 2~3 제목이 이어질 때는 빈 문단을 넣지 않고 다음 제목 문단의 `prev`에 1200 HWPUNIT을 적용한다. 직전 블록이 제목이거나 문서의 첫 제목·명시적 새 쪽 시작이면 `prev=0`으로 둔다. 자연 쪽 넘김 위치는 한컴이 결정하므로 경량 캐시만으로 페이지 첫 제목 판정을 확정하지 않는다. 수준 1은 `pageBreak=1`을 유지한다. 표 뒤 제목은 아래 표 경계 단일 적용 규칙을 따른다. 파란색 검토 문구나 `##############################` 같은 위치 마커는 산출물에 넣지 않는다.

## 표 흐름과 12pt 경계

- 기본은 `글자처럼 취급`(`treatAsChar=1`)이다. 표 열 너비 재배분 **후** 모든 셀의 줄 수·`lineseg` 폭·행 높이·표 전체 높이를 다시 계산한다. 전체 표 높이가 `pagePr.height - margin.top - margin.bottom - margin.header - margin.footer`를 초과하는 경우에만 `treatAsChar=0`과 `pageBreak=CELL`로 셀 단위 나눔을 적용한다. 한글은 본문 편집 영역에서 위아래 여백과 머리말·꼬리말 여백을 모두 제외한다. [한컴 공식 도움말: 격자 기준 위치](https://help.hancom.com/hoffice/multi/ko_kr/hwp/view/grid/grid%28basic_position%29.htm)
- 현재 쪽에 남은 공간 부족은 floating 전환 근거가 아니다. 한 쪽 안에 들어가는 표는 inline을 유지해 한컴이 다음 쪽으로 통째로 넘길 수 있게 한다. 한 셀 자체가 한 쪽보다 높으면 CELL로도 안전하게 나눌 수 없으므로 출력을 중단하고 내용 분리·upstream 편집을 요청한다.
- 표→본문, 표→목록, 표→수준 2~3 제목, 본문·목록·제목→표, 표→표 모두 12pt 경계를 둔다. 다음 문단이 수준 1 등 `pageBreak=1`이면 그 경계는 0이다.
- **여백 소유자 하나:** 직전 표가 floating이면 그 표의 바깥 아래 여백을 1200으로 둔다. 그렇지 않고 다음 표가 floating이면 그 표의 바깥 위 여백을 1200으로 둔다. 그 외 inline 경계는 다음 문단의 `prev=1200`을 사용한다. 다른 위아래 바깥 여백과 문단 `next`는 0으로 두어 12pt를 중복하지 않는다. 좌우 바깥 여백은 보존한다.
- 앵커 문단 캐시는 inline 표의 실제 계산 높이를 반영한다. floating 표는 글자 앵커 높이를 사용하고 바깥 여백으로 흐름 공간을 확보한다. 앵커의 줄간격 캐시는 본문 10pt 기준 600 HWPUNIT이며 **표 전체 높이의 60%로 확대하지 않는다**. 표 셀 160%는 별도로 유지한다.
- 이 계산은 글꼴 메트릭 기반 추정이며 실제 한컴 쪽 수의 증명이 아니다. 쪽 높이 근처의 경계 사례, 긴 셀, 자연 쪽 넘김의 제목 간격은 실제 한컴에서 확인한다. 실제 한 쪽에 들어가는 것으로 확인된 표는 inline 원칙을 우선하며, 수동 보정은 생성기 재적용과 섞지 않고 upstream 편집 경로와 검증 기록에 남긴다.

## 번호 목록

`1. 항목`, `10. 항목`은 번호를 보존한 목록이다. 글머리표와 같은 기준 위치 3200 HWPUNIT을 사용하되, 번호와 뒤 공백의 실제 10pt 맑은 고딕 폭을 올림한 값을 `w`라 할 때 왼쪽 `3200+w`, 첫 줄 `-w`로 설정한다. 후속 줄 `horzpos`는 `3200+w`, 줄 폭은 본문 폭에서 그 위치를 뺀 값이다. 번호 자릿수가 달라도 같은 항목의 첫 본문 글자와 후속 줄이 정렬된다. 번호 앞 일반 공백을 추가하지 않으며 숫자로 시작하는 목차 항목·개요 제목은 목록으로 오인하지 않는다.

본문 표에서 `rowAddr=0`인 모든 셀과 `colAddr=0`인 모든 셀은 교집합 한 셀만이 아니라 해당 행·열 전체를 가로 가운데 정렬하고 세로 중앙에 맞춘다. `rowAddr>0`이면서 `colAddr>0`인 나머지 셀은 양쪽 정렬을 사용하지 않고 가로 왼쪽 정렬한다. 1행 음영과 모든 셀 160% 줄간격은 유지한다.

본문 목록의 `• ` 폭과 -800 HWPUNIT 내어쓰기 차이는 10pt 맑은 고딕 기준 0.1mm 안에서 맞춘다. 일반 공백과 문단 들여쓰기를 동시에 적용하거나, `lineseg` 후속 줄을 첫 줄 글머리표 위치로 되돌리지 않는다. 공식 양식이 `Ⅰ. → 1. → 가.`처럼 다른 번호·들여쓰기 체계를 지정한 문서는 이 경량 기본값을 강제하지 않고 upstream 양식 보존 경로를 사용한다.

경량 모드가 처리하지 않는 문서는 upstream `hwpx` 경로로 전환한다. 사용자가 별도 확인하지 않은 임의 XML 규칙이나 폰트 대체를 추가하지 않는다.
