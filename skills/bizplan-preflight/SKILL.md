# 목적

제출본의 마지막 사고를 잡고 `준비 / 조건부 준비 / 보완 필요` 상태와 남은 사람 확인사항을 명확히 보고함

# 작업 시작 전 사용자 이해 확인

다른 모든 절차보다 먼저 [작업 시작 전 사용자 이해 확인](references/12-user-confirmation-gate.md)을 적용함. 최초 응답에서는 요청 목적·예상 입력·점검 범위·산출물·핵심 가정을 설명하고, 사용자가 그 설명을 본 뒤 별도 메시지로 동의할 때까지 읽기 전용 파일 탐색을 포함한 어떤 점검도 시작하지 않음. 수정사항이나 실질적인 범위 변경이 있으면 이해 내용을 다시 설명하고 재확인함. 이 확인은 제출·파일 수정·사람 확인에 필요한 후속 승인을 대체하지 않음

# 진행 기본값

- 현재 대화와 작업 폴더에서 제출 후보, 기준 공고, 양식, 발표자료를 먼저 찾고 이미 제공된 파일을 다시 요청하지 않음
- 실제로 확인한 항목과 파일 형식상 확인하지 못한 항목을 구분함
- 기본은 읽기 전용 점검이며, 사용자가 수정까지 명시한 경우에만 최소 범위로 변경함
- 최종 문서의 레이아웃을 확인하거나 수정된 제출 후보 파일을 만들 때는 [작업 파일 처리](references/07-artifact-workflow.md)를 읽고 페이지 렌더와 산출물 버전 상태를 기준으로 판단함
- 여러 최신 산출물의 내용 정합성과 수정 후 연동 상태는 [최신 산출물 간 내용 연동](references/11-artifact-synchronization.md)을 기준으로 확인함
- HWPX 제출 후보는 `bizplan-hwpx` 검증 기록에서 원본 보존, open-safety, readback, 프리뷰와 한컴 전체 페이지 관찰 증거를 확인함

# 원칙

- 자동검사는 보조도구이며 키워드 부재만으로 제출 불가를 판정하지 않음
- 제출 가능 여부는 공식 요건, 미해결 빈칸, 직접 모순, 필수 증빙을 중심으로 판단함
- 사용자가 수정까지 요청하지 않으면 문제 위치와 조치만 보고함

# 점검 순서

## 1. 파일·버전

- 올바른 공고·양식·과제명·기관명·파일명인지. 제출처 지정이 없으면 `DXS-[사업코드]-[문서유형]-[파일제목]-[YYYYMMDD]-vX.Y.[확장자]`와 승인 코드표를 적용했는지
- 최신 계획서와 발표자료인지
- `08_작성중`, `09_검토_수정`, `10_제출본`을 통틀어 산출물군별 현재본이 하나인지, 이전본 경로가 `98_이전버전/산출물_버전이력.md`와 일치하는지
- `산출물_연동현황.md`의 기준 원천·현재 버전이 실제 파일과 일치하는지, 필수 산출물에 `연동 대기`, `차단`, `승인 필요`가 남았는지
- 변경이력과 최종 수정일이 맞는지
- 제출용 파일에 주석·변경추적·숨김텍스트가 남지 않았는지
- HWPX 기준본·출력본 SHA-256, 엔진 버전과 검증 기록이 제출 후보와 일치하는지

## 2. 양식·편집

- 제목·번호·표 구조·필수서식이 유지되었는지
- 페이지 제한, 글꼴·여백·서명·합계·첨부요건을 지켰는지
- 제목 계층과 들여쓰기가 통일되었는지
- 명사형 종결과 마침표 규칙이 통일되었는지
- 그림-그림, 표-표가 설명 없이 연속되는지
- 캡션·본문 참조·번호가 일치하는지
- 표·그림 잘림, 너무 작은 글자, 고립 제목이 없는지
- HWPX를 한컴에서 실제로 열어 첫 페이지부터 마지막 페이지까지 확인했고 화면 증거가 있는지

## 3. 완결성

- `TODO`, `TBD`, `〈확인 필요〉`, 빈칸, 예시문이 남았는지
- 연차표의 빈 셀이 누락인지 미해당인지 표시되었는지
- 양식의 작성지침이 최종본에 불필요하게 남거나 필요한 라벨이 삭제되지 않았는지

## 4. 수치·정합성

- 과제기간, 예산, 인원, 가중치 합계
- 최종목표·연차목표·성과지표·요약문·발표자료
- 공정·설비·모델·Agent·산출물 수
- 기관명·약어·용어와 표·그림 번호
- 누적값과 연차값, 분자·분모, 단위

## 5. KPI·증빙

- 지표 유형에 맞는 정의·목표·연차·책임·증빙
- 성능형의 기준선·산식·시험대상·시료·반복·기간·검증
- 데이터형의 산정근거·처리단계·품질·AI 활용
- 공인시험이 가능한 지표와 로그·현장확인·제3자 검토가 적합한 지표의 구분
- 출처 없는 시장·산업최고·세계최고 주장이 없는지

## 6. 역할·실증·위험

- 제공받는 기술과 직접개발 범위
- 기관별 책임과 결과물
- 실증 승인, 안전, 실패·중단·복귀와 책임주체
- 일정지연·성능미달·데이터 부족의 대응
- 외부용역과 연구개발 핵심의 경계

## 7. 사람 확인

다음은 자동 확정하지 않고 질문으로 올림

- 수치의 사실성과 서명 주체
- 목표 달성 가능성에 대한 실무진 동의
- 기관 역할과 시험기관의 실제 수용 여부
- 민감한 도면·공정·개인·거래정보 포함 여부
- 최신 버전 확정

# 선택형 스크립트

평문 파일이 있을 때만 다음을 사용할 수 있음

```bash
python scripts/advisory_lint.py plan.txt --nominal-ending --no-terminal-period
```

`--strict`는 미해결 플레이스홀더와 중복 캡션처럼 고신뢰 오류만 실패코드로 처리함

스크립트 결과는 본문·표·페이지의 직접 확인을 대체하지 않음

# 최종 출력

- 상태: `준비 / 조건부 준비 / 보완 필요`
- Gate 이슈
- High 이슈
- 편집·가독성 이슈
- 사람 확인사항
- 제출 전 조치 순서
- 확인하지 못한 항목과 이유
- 최신 산출물 연동 상태와 미해결 영향

기본 읽기 전용 점검에서는 파일·버전 이력·연동현황을 수정하거나 이동하지 않음. 사용자가 수정까지 요청해 새 제출 후보와 영향을 받는 다른 최신 산출물의 후보를 만들고 모두 검증한 경우에만 각 기존 현재본 묶음을 `98_이전버전`으로 보관하고 두 이력을 갱신함

HWPX의 한컴 실제 관찰 증거가 없으면 내용 점검이 통과해도 상태를 `준비`로 판정하지 않음

제출에 함께 쓰이는 필수 산출물에 현재 내용과 다른 `연동 대기`, `차단`, `승인 필요`가 남으면 Gate로 보고 상태를 `보완 필요`로 판정함. 이를 `조건부 준비`로 낮춰 우회하지 않음

# 금지

- 단순 키워드가 없다는 이유로 실패 처리하지 않음
- 공인시험을 모든 KPI에 일괄 강제하지 않음
- 문서 내용이 확인되지 않았는데 `이상 없음`이라고 쓰지 않음
- 마지막 단계에서 새로운 목표·기관·수치를 생성하지 않음
- `render_preview`만으로 HWPX 실한컴 검증 완료라고 판정하지 않음
