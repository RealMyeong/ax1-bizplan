# 목적

제출본의 마지막 사고를 잡고 `준비 / 조건부 준비 / 보완 필요` 상태와 남은 사람 확인사항을 명확히 보고함

# 진행 기본값

- 현재 대화와 작업 폴더에서 제출 후보, 기준 공고, 양식, 발표자료를 먼저 찾고 이미 제공된 파일을 다시 요청하지 않음
- 실제로 확인한 항목과 파일 형식상 확인하지 못한 항목을 구분함
- 기본은 읽기 전용 점검이며, 사용자가 수정까지 명시한 경우에만 최소 범위로 변경함
- 최종 문서의 레이아웃을 확인할 때는 [작업 파일 처리](references/07-artifact-workflow.md)를 읽고 페이지 렌더를 기준으로 판단함

# 원칙

- 자동검사는 보조도구이며 키워드 부재만으로 제출 불가를 판정하지 않음
- 제출 가능 여부는 공식 요건, 미해결 빈칸, 직접 모순, 필수 증빙을 중심으로 판단함
- 사용자가 수정까지 요청하지 않으면 문제 위치와 조치만 보고함

# 점검 순서

## 1. 파일·버전

- 올바른 공고·양식·과제명·기관명·파일명인지
- 최신 계획서와 발표자료인지
- 변경이력과 최종 수정일이 맞는지
- 제출용 파일에 주석·변경추적·숨김텍스트가 남지 않았는지

## 2. 양식·편집

- 제목·번호·표 구조·필수서식이 유지되었는지
- 페이지 제한, 글꼴·여백·서명·합계·첨부요건을 지켰는지
- 제목 계층과 들여쓰기가 통일되었는지
- 명사형 종결과 마침표 규칙이 통일되었는지
- 그림-그림, 표-표가 설명 없이 연속되는지
- 캡션·본문 참조·번호가 일치하는지
- 표·그림 잘림, 너무 작은 글자, 고립 제목이 없는지

## 3. 완결성

- `TODO`, `TBD`, `〈확인 필요〉`, 빈칸, 예시문이 남았는지
- 연차표의 빈 셀이 누락인지 미해당인지 표시되었는지
- 양식의 작성지침이 최종본에 불필요하게 남거나 필요한 라벨이 삭제되지 않았는지

## 4. 수치·정합성

- 과제기간, 예산, 인원, 가중치 합계
- 최종목표·연차목표·성과지표·요약문·발표자료
- 공정·설비·모델·Agent·산출물 수
- 기관명·약어·용어와 표·그림 번호
- 누적값과 연차값, 분자·분모, 단위

## 5. KPI·증빙

- 지표 유형에 맞는 정의·목표·연차·책임·증빙
- 성능형의 기준선·산식·시험대상·시료·반복·기간·검증
- 데이터형의 산정근거·처리단계·품질·AI 활용
- 공인시험이 가능한 지표와 로그·현장확인·제3자 검토가 적합한 지표의 구분
- 출처 없는 시장·산업최고·세계최고 주장이 없는지

## 6. 역할·실증·위험

- 제공받는 기술과 직접개발 범위
- 기관별 책임과 결과물
- 실증 승인, 안전, 실패·중단·복귀와 책임주체
- 일정지연·성능미달·데이터 부족의 대응
- 외부용역과 연구개발 핵심의 경계

## 7. 사람 확인

다음은 자동 확정하지 않고 질문으로 올림

- 수치의 사실성과 서명 주체
- 목표 달성 가능성에 대한 실무진 동의
- 기관 역할과 시험기관의 실제 수용 여부
- 민감한 도면·공정·개인·거래정보 포함 여부
- 최신 버전 확정

# 선택형 스크립트

평문 파일이 있을 때만 다음을 사용할 수 있음

```bash
python scripts/advisory_lint.py plan.txt --nominal-ending --no-terminal-period
```

`--strict`는 미해결 플레이스홀더와 중복 캡션처럼 고신뢰 오류만 실패코드로 처리함

스크립트 결과는 본문·표·페이지의 직접 확인을 대체하지 않음

# 최종 출력

- 상태: `준비 / 조건부 준비 / 보완 필요`
- Gate 이슈
- High 이슈
- 편집·가독성 이슈
- 사람 확인사항
- 제출 전 조치 순서
- 확인하지 못한 항목과 이유

# 금지

- 단순 키워드가 없다는 이유로 실패 처리하지 않음
- 공인시험을 모든 KPI에 일괄 강제하지 않음
- 문서 내용이 확인되지 않았는데 `이상 없음`이라고 쓰지 않음
- 마지막 단계에서 새로운 목표·기관·수치를 생성하지 않음
