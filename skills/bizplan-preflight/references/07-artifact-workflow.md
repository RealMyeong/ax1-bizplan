# 작업 파일 처리와 시각 검증

실제 문서·발표자료 파일을 만들거나 수정할 때만 적용함. 텍스트 문안만 요청된 경우에는 파일을 생성하지 않음

## 1. 기준 파일과 수정본

- 사용자가 지정한 파일이 있으면 그것을 기준으로 삼고, 지정이 없으면 파일명·수정일·문서 내용으로 최신 후보를 식별함
- 어느 파일이 최신인지 확정할 수 없고 선택에 따라 결과가 달라질 때만 질문함
- 원본 덮어쓰기가 명시되지 않으면 별도 수정본을 만들고 기준 파일, 출력 파일, 버전을 보고함
- 수정 범위 밖의 스타일, 내용, 메타데이터와 기존 사용자 변경을 보존함
- 버전이 달라지는 관리 산출물을 만들면 [산출물 최신본·이전버전 관리](10-artifact-version-management.md)를 적용함. 새 버전 검증 후 같은 산출물군의 기존 현재본 묶음을 `98_이전버전`으로 옮기고 이력표를 갱신함
- 읽기 전용 검토, 버전 판정이 모호한 경우와 새 버전 검증이 끝나지 않은 경우에는 기존 파일을 이동하지 않음

## 2. 형식별 처리

- 편집 가능한 원본이 있으면 해당 형식에 맞는 문서·스프레드시트·프레젠테이션 도구로 수정함
- PDF만 있으면 먼저 텍스트와 페이지 이미지를 확인하고, 편집 가능한 원본 없이 동일 서식을 재현할 수 있다고 단정하지 않음
- HWPX를 만들거나 수정할 때는 `bizplan-hwpx`를 적용하고, 별도 설치된 upstream `hwpx` 스킬과 MCP의 원본 보존·dry-run·open-safety·readback 절차를 사용함
- 바이너리 HWP는 직접 편집하지 않음. 원본을 보존한 뒤 한컴오피스에서 HWPX 사본으로 변환하고 변환 손실을 확인한 다음 작업함
- HWPX 실행환경 또는 실제 재개방 검증이 불가능하면 직접 삽입 문안, 위치, DOCX 대안과 미검증 한계를 명시함
- 다른 형식으로 변환할 때 표, 그림, 수식, 글꼴과 페이지 나눔의 손실 가능성을 확인함

## 3. 시각 검증

수정본은 가능한 경우 페이지나 슬라이드 이미지로 렌더하여 다음을 확인함

- 제목 계층, 들여쓰기, 글꼴과 문단 간격
- 표·그림 잘림, 캡션과 본문 참조, 페이지 경계
- 빈 페이지, 고립 제목, 지나치게 작은 글자
- 수정 구간 앞뒤의 레이아웃 변화

내용 검사만 통과하고 렌더 결과를 보지 못한 경우 `시각 검증 완료`라고 보고하지 않음

HWPX는 `render_preview` 성공만으로 한컴 실제 검증 완료라고 판단하지 않음. 한컴에서 첫 페이지부터 마지막 페이지까지 열어 표·글자·페이지 경계를 관찰하고 화면 증거를 남기지 못하면 `한컴 시각 검증 대기`로 보고함

## 4. 완료 보고

- 기준 파일과 수정본
- 실제 변경 위치와 변경 요약
- 수행한 내용·수치·시각 검증
- 확인하지 못한 형식 요소와 이유
- 사람의 승인 또는 원본 프로그램 확인이 필요한 항목
