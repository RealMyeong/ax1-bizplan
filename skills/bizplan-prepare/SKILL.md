# 목적

빈 프로젝트 최상위 폴더에 사업계획서의 자료 수집, 사업 구체화, 작성, 검토, 버전 보관과 제출 흐름을 반영한 작업공간을 안전하게 구축함

# 작업 시작 전 사용자 이해 확인

다른 모든 절차보다 먼저 [작업 시작 전 사용자 이해 확인](references/03-user-confirmation-gate.md)을 적용함. 최초 응답에서는 요청 목적·예상 대상 폴더·생성 범위·산출물·안전 가정을 설명하고, 사용자가 그 설명을 본 뒤 별도 메시지로 동의할 때까지 경로 확인, 폴더 조회, 스크립트 실행과 구조 생성을 시작하지 않음. 수정사항이나 실질적인 대상·생성 범위 변경이 있으면 이해 내용을 다시 설명하고 재확인함. 이 확인은 경로 충돌이나 파괴적 작업에 필요한 별도 승인을 대체하지 않음

# 기본 동작

- 사용자가 지정한 폴더가 있으면 그 폴더를 사용하고, 지정하지 않았으면 현재 프로젝트의 최상위 작업 폴더를 사용함
- 대상 경로를 절대경로로 확인한 뒤 [작업공간 생성 스크립트](scripts/setup_workspace.ps1)를 실행함
- 이미 존재하는 폴더, 준비현황 파일, 산출물 연동현황과 버전 이력은 유지하고 없는 항목만 생성함
- 최상위에 기존 자료가 있어도 자동으로 이동·이름변경·삭제하지 않음. 필요한 경우 생성 완료 후 권장 이동 위치만 제안함
- 기존 작업공간에 여러 버전이 있어도 준비 실행만으로 정리하지 않음. 실제 새 버전 전환이나 명시적인 정리 요청이 있을 때만 [산출물 버전 관리](references/01-artifact-version-management.md)를 적용함
- [최신 산출물 간 내용 연동](references/02-artifact-synchronization.md)에 사용할 빈 연동현황을 만들지만, 준비 실행만으로 기존 파일의 기준 원천·영향 관계·연동 상태를 추정해 채우지 않음
- 프로젝트 자료의 내용 작성이나 사업계획서 초안 작성은 이 스킬의 범위가 아님. 준비가 끝난 뒤 별도 요청이 있으면 `bizplan-draft`를 사용함

# 안전 조건

- 드라이브 루트, 사용자 프로필 루트, Codex 스킬 설치 폴더를 대상 프로젝트로 사용하지 않음
- 현재 폴더가 사용자가 의도한 프로젝트 최상위인지 확정할 수 없고 선택에 따라 다른 위치에 파일이 생기면 한 번만 확인함
- 재귀 삭제·이동, 원본 덮어쓰기, 기존 폴더명 일괄변경을 수행하지 않음
- 같은 이름의 파일이 있어 폴더를 만들 수 있으면 생성 전에 충돌을 보고하고 중단함

# 표준 구조

다음 최상위 폴더와 작성·검토·제출용 세부폴더를 생성함

| 폴더 | 용도 |
|---|---|
| `00_공고_RFP` | 공고문, RFP, 공식 Q&A, 평가배점표 |

| `02_사업기획_구현구상` | 사업 아이디어, 구현 브리프, 운영 시나리오, 시스템 구성 |
| `03_기관_인력_역할` | 기관현황, 참여인력, 역할분담, 자격·증빙 |
| `04_기술_선행성과` | 보유기술, 특허, 논문, 선행과제, 기술자료 |
| `05_시장_정책_사업화` | 시장·정책 근거, 고객·수요 증빙, 사업화 자료 |
| `06_데이터_실증_KPI` | 데이터, 실증현장, 기준선, KPI, 시험·검증 자료 |
| `07_예산_일정` | 예산근거, 견적, 연차일정, 장비·외주 계획 |
| `08_작성중` | 본문, 표·그림, 근거·수치원장 |

# 작업 절차

## 1. 대상 확정

- 현재 작업 폴더와 사용자가 지정한 경로를 확인함
- 대상 폴더가 존재하는 디렉터리인지 확인함
- 안전 조건에 해당하면 실행하지 않고 정확한 프로젝트 폴더를 요청함

## 2. 구조 생성

PowerShell에서 다음과 같이 스크립트를 실행함

```powershell
& "<skill-folder>\scripts\setup_workspace.ps1" -Root "<absolute-project-root>"
```

반환된 `created_directories`, `existing_directories`, `checklist_status`, `version_ledger_status`, `sync_ledger_status`를 확인함

## 3. 검증

- 표준 최상위 폴더와 세부폴더가 모두 디렉터리로 존재하는지 확인함
- `사업계획서_준비현황.md`가 UTF-8로 정상 생성되었는지 확인함
- `산출물_연동현황.md`가 UTF-8로 정상 생성되었는지 확인함
- `98_이전버전/산출물_버전이력.md`가 UTF-8로 정상 생성되었는지 확인함
- 스크립트를 다시 실행해 새 항목이 추가되거나 기존 체크리스트·연동현황·버전 이력이 덮어써지지 않는지 확인함
- 최상위의 기존 파일을 읽기 전용으로 목록화하고, 명백한 경우에만 권장 폴더를 제안함. 실제 이동은 별도 승인을 받음

# 완료 보고

- 준비한 프로젝트 최상위 경로
- 새로 생성된 폴더 수와 이미 존재한 폴더 수
- 준비현황 체크리스트 링크
- 산출물 연동현황 링크
- 산출물 버전 이력과 이전버전 보관함 링크
- 충돌하거나 생성하지 못한 항목
- 기존 파일이 있으면 권장 분류 위치
- 다음 단계로 공고·RFP·양식을 어느 폴더에 넣을지 간단히 안내함

# 금지

- 현재 위치가 불명확한데 추측하여 넓은 상위 폴더에 구조를 생성하지 않음
- 기존 자료를 사용자 승인 없이 새 폴더로 이동하지 않음
- 준비현황 파일을 재실행 시 초기화하거나 덮어쓰지 않음
- 산출물 연동현황과 버전 이력을 재실행 시 초기화하거나 덮어쓰지 않음
- 준비 실행만으로 기존 산출물의 최신본을 추정하거나 이전 파일을 `98_이전버전`으로 이동하지 않음
- 이 스킬 실행만으로 사업계획서 본문, 가정 수치나 기관 정보를 생성하지 않음
