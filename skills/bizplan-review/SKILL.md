# 목적

문서를 평가위원이 읽는 순서로 검토하고, 문제 위치·판단근거·예상 질문·수정전략·삽입 가능한 문안을 제공함

# 진행 기본값

- 현재 대화와 작업 폴더에서 기준문서와 최신본을 먼저 찾고, 이미 제공된 파일을 다시 요청하지 않음
- 자료가 일부 없으면 확인 가능한 범위부터 검토하고, 확인하지 못한 범위와 판단 영향을 명시함
- `검토`, `평가`, `진단` 요청은 읽기 전용으로 처리하며, 사용자가 수정까지 명시한 경우에만 파일을 변경함
- 문서 파일의 레이아웃·표·그림을 확인해야 하면 [작업 파일 처리](references/07-artifact-workflow.md)를 읽고 렌더 기반으로 점검함

# 근거 사용 원칙

- 공고문·RFP·양식·배점표를 최우선으로 함
- 평가위원 의견은 평가관점 근거로 사용함
- 작성기관의 반영내용은 대응 사례이며 검증된 정답으로 취급하지 않음
- 동일 사업의 반복 관점은 사업 프로파일에만 적용함
- 평가의견 빈도와 실제 감점 크기를 같은 것으로 보지 않음

# 검토 절차

## Pass 0. 입력과 범위

- 기준 공고·양식·계획서 버전, 평가배점표 확보 여부를 명시함
- 검토 제외범위와 자료 한계를 선언함
- 발표자료가 있으면 계획서와 어느 문서가 최신인지 지정함

## Pass 1. 양식·문체·편집

[범용 코어 원칙](references/01-core-principles.md)과 [양식·문체·편집 가이드](references/02-format-style-guide.md)를 적용함

- 제목·번호·들여쓰기·표 구조 변경 여부
- 양식 내 작성지침·분량·필수항목 준수
- 명사형 종결과 마침표 규칙 통일
- 그림·표의 연속배치, 캡션, 본문 참조, 가독성
- 빈칸, 안내문 잔존, 잘린 표·그림

## Pass 2. RFP·범위·논리

- RFP 요구와 최종목표·세부목표·연차계획의 대응
- 대상 제품·공정·서비스·수요자의 범위
- 필요성→목표→수행내용→검증→성과의 인과
- 공통 설명과 과제 고유 차별성의 구분

## Pass 3. 정량지표

[KPI 프레임워크](references/04-kpi-framework.md)를 적용함

- 지표 유형별 필수필드를 확인함
- 성능형은 기준선·산식·대상·시료·반복·기간·검증을 확인함
- 데이터형은 발생원·처리단계·산정근거·품질·AI 활용을 확인함
- 실증·성과·사업화 지표에는 각 유형에 맞는 완료기준과 증빙을 적용함
- 연차별 빈칸과 계획서·발표자료 간 수치 불일치를 확인함

## Pass 4. 데이터·기술·실증

- 입력·출력·기술 난제·검증환경의 구체성
- 데이터 발생원, 처리단계, 식별·동기·품질·이상데이터·계보
- 실제 모델 또는 서비스에 활용되는 경로
- PoC→현장 적용, 안전, Human-in-the-loop, 실패·복귀 절차

## Pass 5. 역할·추진체계·사업화

- 주관·공동·수요·총괄·연계과제의 책임경계
- 기관별 연차 산출물과 KPI 책임
- 인터페이스, 전달·인수, 검증주기, 일정지연·성능미달 대응
- 기술이전 패키지, 목표시장, 적용기업·라인, 매출·수익·IP
- 연구책임자·전문인력·외부용역의 수행가능성

## Pass 6. 사업 프로파일

대상이 PI-LAM 제조 Physical AI 유사과제일 때만 [PI-LAM 프로젝트 프로파일](references/05-project-profile.md)과 [평가위원 관점 프레임](references/06-evaluator-lens.md)을 적용함

프로파일의 구체적 수치를 새 문서의 목표로 복사하지 않음

## Pass 7. 전역 정합성

- 과제명, 기관명, 기간, 예산, 공정·모델·Agent·산출물 수
- 최종목표, 연차표, 성과지표, 요약문, 발표자료의 숫자
- 표·그림 번호, 약어, 용어 정의
- 검토의견 반영 위치와 실제 본문 내용

# 리스크와 근거신뢰도

리스크

- `Gate`: 양식·적격성·RFP 직접위반·핵심 수치충돌
- `High`: 평가 판단에 큰 영향을 줄 가능성이 높은 구조·측정·역할 공백
- `Medium`: 구체성·일관성·설득력을 약화시키는 문제
- `Editorial`: 표기·문체·가독성 문제

근거신뢰도

- `High`: 공식 규칙 또는 문서 내 직접 모순
- `Medium`: 반복 평가관점 또는 강한 문맥 근거
- `Low`: 단일 사례·추론·추가 확인이 필요한 판단

빈도만으로 Gate 또는 High를 자동 부여하지 않음

# 지적 1건의 출력

```text
[High | 근거신뢰도 Medium] KPI-03 측정설계 불충분
위치          6장 나, 표 18, p.00
현재 내용     ...
판단근거      RFP 요구 / 양식 지침 / 문서 내 불일치 / 사업 프로파일 관점
예상 평가질문 ...
수정전략      ...
교정문안      직접 붙여넣을 수 있는 문장 또는 표 셀
확인 필요     실측값, 담당기관, 시험조건 등
```

# 출력 순서

1. 검토 기준과 한계
2. 종합 판단
3. 유지할 강점
4. Gate·High·Medium·Editorial 순 보완사항
5. 전역 정합성 표
6. 자료·의사결정 요청
7. 잔여 리스크

# 금지

- `구체화 필요`로 끝내지 않음
- 근거 없는 수치가 든 교정문안을 만들지 않음
- 반영내용이 적혀 있다는 이유만으로 평가의견을 해소 처리하지 않음
- 제조 AI 전용 키워드가 없다는 이유로 다른 분야 계획서를 감점하지 않음
- 자동검사 결과만으로 제출 가능 여부를 확정하지 않음
