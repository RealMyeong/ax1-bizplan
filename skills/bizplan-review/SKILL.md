# 목적과 경계

작성된 국가 R&D·공모 사업계획서를 평가위원 관점으로 검토한다. 문제 위치·판단근거·예상 질문·수정전략·삽입 가능한 교정문안을 제공한다. 신규 초안은 `bizplan-draft`, 실제 의견 반영은 `bizplan-revise`, 제출 직전 형식·완결성 점검은 `bizplan-preflight`로 구분한다.

# 작업 시작 전 사용자 이해 확인

[사용자 이해 확인](references/12-user-confirmation-gate.md)에 따라 목적·예상 입력·검토 범위와 제외·결과·주요 가정을 설명하고, 별도 메시지의 동의 뒤 읽기 전용 탐색·검토를 시작한다. [범위와 실행 판단](references/14-task-execution.md)을 적용하며 동일 요청의 동의를 반복하지 않는다.

# 기준과 적용 범위

동의 후 현재 대화와 작업 폴더에서 기준 공고·RFP·Q&A·공식 양식·배점표·최신 계획서를 확인한다. 일부 자료가 없으면 가능한 부분을 검토하고 판단 한계를 밝힌다. 이미 제공된 파일을 재요청하지 않는다.

[코어 원칙](references/01-core-principles.md)을 적용한다. 공식 자료와 승인 사실을 우선하며 평가의견·작성기관 반영문안·선정 결과를 구분한다. 의견 빈도는 감점 크기나 인과관계의 증거가 아니다.

# 검토 축

전체 사전검토는 다음 축을 빠짐없이 확인한다. 특정 항목 요청에는 그 범위와 직접적인 정합성 영향만 검토하며 무관한 축을 강제하지 않는다.

- 양식·편집: [양식 가이드](references/02-format-style-guide.md)의 제목·번호·들여쓰기·필수 셀·분량·문체·캡션·참조·잘림
- 요구와 논리: RFP→최종·세부목표→수행내용→연차→검증→성과의 대응, 대상·범위·차별성
- 지표: [KPI 프레임워크](references/04-kpi-framework.md)의 유형별 정의·기준선·산정·대상·측정·책임·증빙, 연차 빈칸과 발표자료 수치
- 기술·데이터·실증: 입력·출력·기술 난제·검증환경, 발생원·품질·동기·계보·활용 경로, 현장 적용·안전·사람 개입·실패 복귀
- 역할·실현가능성·사업화: 개발·제공·통합·인수 책임과 인터페이스, 연차 산출물·KPI 책임, 인력·외주·자원·지연 대응, 시장·고객·수익·IP·이전 패키지
- 전역 정합성: 과제명·기관·기간·예산·개수·용어·약어·최종/연차/요약/발표 수치, 실제 반영 위치
- 사업별 관점: PI-LAM 제조 Physical AI 등 적용 조건이 맞을 때만 [프로파일](references/05-project-profile.md)과 [평가 렌즈](references/06-evaluator-lens.md)를 추가한다. 다른 분야에 제조 AI 키워드를 요구하지 않는다.

여러 현재 산출물의 불일치는 [기준 원천과 연동](references/11-artifact-synchronization.md)으로 판단한다. 검토 제안은 승인된 변경 원천이 아니며 다른 문서에 자동 역전파하지 않는다.

# 지적과 결과

지적은 `위치 / 현재 내용 / 판단근거 / 예상 평가질문 / 수정전략·교정문안 / 필요한 자료`로 추적 가능하게 쓴다. 형식은 범위에 맞게 표나 짧은 문단을 선택한다. `구체화 필요`만 쓰거나 근거 없는 수치를 넣지 않는다.

- 리스크: `Gate`(공식 직접위반·핵심 수치충돌), `High`(평가에 큰 영향을 주는 구조·측정·책임 공백), `Medium`(구체성·정합성), `Editorial`(표기·가독성)
- 근거신뢰도: `High`(공식 규칙·직접 모순), `Medium`(반복 관점·강한 문맥), `Low`(단일 관찰·추론)
- 종합 판단과 중요한 지적부터 보고하고, 기준·한계·유지할 강점·필요한 결정·잔여 위험을 덧붙인다. 문제가 없는 축의 빈 보고서 틀을 출력하지 않는다.

# 파일·검증 경계

검토는 읽기 전용이다. 수정 요청 없이는 파일·버전 이력·연동현황을 생성·수정·이동하지 않는다. 레이아웃 확인이나 별도 검토보고서 파일 요청에는 [파일 검증](references/07-artifact-workflow.md)을 적용한다.

보고서 파일을 요청한 경우만 [버전 관리](references/10-artifact-version-management.md)에 따라 `검토보고서` 산출물군을 전환하고 검토 대상 계획서는 그대로 둔다. 자동 lint나 키워드 부재만으로 제출 가능·불가를 확정하지 않는다.

설치·업데이트 요청에만 [직전 설치본 백업](references/13-skill-backup-retention.md)을 적용한다.
