# 목적

의견 한 건에 보이는 문장만 고치지 않고, 원인과 영향범위를 찾아 양식·수치·표·연차·역할을 함께 수정함

# 작업 시작 전 사용자 이해 확인

다른 모든 절차보다 먼저 [작업 시작 전 사용자 이해 확인](references/12-user-confirmation-gate.md)을 적용함. 최초 응답에서는 요청 목적·예상 입력·수정 범위·산출물·핵심 가정을 설명하고, 사용자가 그 설명을 본 뒤 별도 메시지로 동의할 때까지 원문·검토의견 탐색이나 수정 작업을 시작하지 않음. 수정사항이나 실질적인 범위 변경이 있으면 이해 내용을 다시 설명하고 재확인함. 이 확인은 수정 기준 확정과 실제 문서 반영 승인을 대체하지 않음

# 진행 기본값

- 현재 대화와 작업 폴더에서 원문, 검토의견, 최신 기준자료를 먼저 찾고 이미 제공된 파일을 다시 요청하지 않음
- 승인되지 않은 수치·기관 역할은 추정하지 않되, 그 밖의 수정은 가능한 범위까지 먼저 진행함
- 사용자가 실제 문서의 생성·수정을 요청하면 [작업 파일 처리](references/07-artifact-workflow.md)를 읽고 원본 보존, 수정본 생성, 렌더 확인과 검증 후 버전 전환을 수행함
- 수정 결과가 기존 현재본과 의미상 달라지면 [최신 산출물 간 내용 연동](references/11-artifact-synchronization.md)을 읽고 변경 항목의 기준 원천과 다른 최신 산출물의 영향 위치를 판정함
- 기준본이 HWPX이면 수정문안과 전역 영향 위치를 먼저 확정한 뒤 `bizplan-hwpx`로 별도 수정본에 dry-run·commit·readback·한컴 검증을 수행함
- 사용자가 문안만 요청하면 파일을 만들지 않고 직접 삽입 가능한 수정문안과 영향 위치를 제공함

# 입력

- 기준 공고·RFP·양식
- 수정 전 계획서와 버전
- 평가위원·내부 검토의견 원문
- 이미 작성된 반영내용이 있으면 그 문안
- 승인된 수치·역할·결정사항

# 절차

## 1. 의견 원문 보존

[검토의견 반영 대장](assets/review-response-matrix.md)에 의견을 요약하지 않고 원문으로 기록함

평가의견과 작성기관의 기존 반영문안을 분리함

## 2. 실제 요구 분해

각 의견을 다음으로 분해함

- 공식 요구인지 평가관점인지
- 범위, 기준, 방법, 책임, 근거, 문체 중 무엇이 부족한지
- 설명 추가, 수치확정, 표 재설계, 기관합의, 자료조사 중 어떤 조치가 필요한지
- 같은 원인이 다른 장에도 있는지
- 다른 의견이나 RFP와 충돌하는지

## 3. 수정 기준 확정

- 상위 공식근거와 최신 기준문서를 확인함
- 반영문안이 이미 있어도 실제 계획서 위치와 내용으로 검증함
- 사례 수치를 복사하지 않음
- 자료가 없으면 `부분 반영`과 확인 항목으로 남김

## 4. 최소 범위 수정

- 제목·표 구조·들여쓰기·문체를 유지함
- 지적된 문제와 전역 영향범위만 수정함
- 통과한 내용을 이유 없이 전면 재작성하지 않음
- 명사형 종결과 마침표 미사용 등 문서 프로파일을 유지함
- 그림·표 추가 시 앞뒤 설명과 번호·본문 참조를 함께 수정함

## 5. 원장·반복 위치와 다른 최신 산출물 동기화

지표·수치·역할이 바뀌면 다음을 모두 검색함

- 요약문과 최종목표
- 연차별 목표·일정
- 성과지표와 산출근거
- 추진체계와 기관별 역할
- 사업화 목표
- 발표자료

문서 내부 검색에 그치지 않고 `08_작성중`, `09_검토_수정`, `10_제출본`의 다른 현재 산출물군과 `산출물_연동현황.md`를 확인함. 승인된 변경 집합을 실제로 소비하는 산출물만 각각 새 버전 후보로 만들고, 모든 필수 후보를 형식별 검증한 뒤 하나의 연동 ID로 전환함. 발표자료·PDF·검토보고서에서만 발견된 고유 값은 상위 원장이나 계획서로 자동 역전파하지 않음

## 6. 대응 상태 판정

- `해소`: 요구사항과 전역 정합성까지 반영함
- `부분`: 수치·합의·증빙이 남음
- `미해소`: 자료 또는 구조상 반영하지 못함
- `보류`: 공식근거 확인 필요
- `충돌`: 다른 요구와 충돌함

## 7. 변경이력

[변경이력 템플릿](assets/change-log-template.md)에 변경근거, 영향 위치, 결정자와 잔여이슈를 기록함

# 출력

1. 의견 분해표
2. 수정전략과 우선순위
3. 직접 삽입 가능한 수정문안 또는 수정된 표
4. 영향받은 전역 위치
5. 검토의견 반영 대장
6. 변경이력
7. 최신 산출물 영향 판정과 함께 연동한 버전·연동 ID
8. 사람의 결정이 필요한 항목

HWPX 파일 수정까지 요청한 경우에는 기준본·수정본 SHA-256, semantic diff, open-safety, readback과 한컴 관찰 상태를 함께 제공함

새 수정본과 필수 연동 후보의 검증이 끝나면 각 산출물군의 기존 현재본과 그 버전에 종속된 연관 파일을 `98_이전버전`으로 보관하고, 현재본·보관본 경로, 버전 이력과 `산출물_연동현황.md` 갱신 결과를 함께 제공함. 하나라도 안전하게 갱신할 수 없으면 에이전트가 만든 후보를 부분 승격하지 않고 연동 대기 또는 차단으로 보고함

# 금지

- 본문에 평가위원에게 해명하는 답변체 문장을 넣지 않음
- 기존 반영문안을 검증 없이 복사하지 않음
- 실측값과 기관합의를 추정하지 않음
- 양식의 제목과 번호를 임의로 재구성하지 않음
- 한 의견을 해소하기 위해 문서 전체 문체를 불필요하게 다시 쓰지 않음
- 바이너리 HWP를 직접 편집하거나 HWPX 원본을 덮어쓰지 않음
