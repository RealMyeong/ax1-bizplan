# 목적과 경계

기존 사업계획서에 평가·검토의견을 반영한다. 지적의 원인과 직접 영향 위치를 찾아 양식·문체를 보존한 수정문안 또는 수정본과 반영 대장을 만든다. 새 초안은 `bizplan-draft`, 읽기 전용 평가는 `bizplan-review`를 사용한다.

# 작업 시작 전 사용자 이해 확인

[사용자 이해 확인](references/12-user-confirmation-gate.md)에 따라 목적·기준자료·수정 범위와 제외·산출물·주요 가정을 설명하고, 별도 메시지의 동의 뒤 탐색·작업을 시작한다. [범위와 실행 판단](references/14-task-execution.md)을 적용하며 동일 범위의 승인·답변을 재사용한다.

# 기준 확보

동의 후 현재 대화·작업 폴더에서 공고·RFP·양식, 수정 전 계획서와 버전, 의견 원문, 기존 반영문안, 승인된 수치·역할·결정을 확인한다. [근거와 양식 보호](references/01-core-principles.md)를 적용한다.

기존 반영문안은 실제 본문과 대조하며 충분한 답변이라고 추정하지 않는다. 부족한 자료에 의존하는 수정만 보류하고 나머지는 진행한다. 실측값·기관 합의·타 사업 수치를 만들어 넣지 않는다.

# 의견 반영

1. [반영 대장](assets/review-response-matrix.md)에 의견 원문과 작성기관 대응을 분리해 보존한다. 공식 요구인지 평가관점인지, 범위·방법·책임·근거 중 무엇이 부족한지와 충돌을 판정한다.
2. 조치를 문안 보완·수치 확정·표 수정·기관 합의·조사로 나누고 근거와 실제 반영 위치를 정한다.
3. [양식·문체](references/02-format-style-guide.md)를 유지하며 지적과 영향 범위만 수정한다. 통과한 부분을 전면 재작성하지 않는다. 본문에는 평가위원에게 해명하는 답변체가 아니라 독자가 사용할 내용을 쓴다.
4. KPI 변경에는 [유형별 지표 기준](references/04-kpi-framework.md)을 적용한다. 요약·최종목표·연차·성과지표·일정·기관 역할·사업화·발표자료의 같은 값을 검색한다.
5. [최신 산출물 연동](references/11-artifact-synchronization.md)에 따라 승인된 변경을 소비하는 현재 문서만 새 후보로 만든다. 발표자료·PDF·검토보고서의 고유 값을 상위 원천으로 자동 역전파하지 않는다.
6. 실제 본문과 전역 정합성까지 재확인해 `해소 / 부분 / 미해소 / 보류 / 충돌`을 판정한다. [변경이력](assets/change-log-template.md)에 근거·위치·결정자·잔여 항목을 남긴다.

# 파일 작업

문안만 요청하면 직접 삽입할 문안과 영향 위치를 제공하고 파일을 만들지 않는다. 파일 수정 요청에는 [파일 처리](references/07-artifact-workflow.md)와 [파일명·버전 관리](references/10-artifact-version-management.md)를 적용한다.

HWPX는 수정문안·위치를 확정한 뒤 `bizplan-hwpx`의 기존 문서 경로로 처리한다. 바이너리 HWP 직접 편집과 원본 HWPX 덮어쓰기를 하지 않는다. 구조·readback·렌더·한컴 관찰은 수행한 상태를 구분해 기록한다.

새 수정본과 필수 연동 후보 검증이 끝난 뒤에만 기존 현재본 묶음을 `98_이전버전`으로 보관하고 버전 이력과 `산출물_연동현황.md`를 갱신한다. 하나라도 안전하게 갱신할 수 없으면 후보를 부분 승격하지 않고 연동 대기·차단으로 보고한다.

# 완료 기준

의견→조치→실제 위치→검증 결과를 추적할 수 있어야 한다. 수정본 또는 문안, 주요 반영·미반영, 전역 영향과 연동 상태, 남은 결정·증빙을 보고한다. 전체 의견이 아니라 한 건만 요청하면 그 건과 영향 범위에 맞는 간단한 대장을 쓴다.

설치·업데이트 요청에만 [직전 설치본 백업](references/13-skill-backup-retention.md)을 적용한다.
